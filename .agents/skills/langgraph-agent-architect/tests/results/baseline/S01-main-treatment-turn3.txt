## Архитектура процесса

**Цель:** принять структурированную заявку, один раз проверить обязательные поля и вернуть итог проверки.

**Выбранный подход:** синхронная функция. Для этого процесса она проще отдельного графа: не нужны LLM, память, циклы или внешние инструменты.

**Поток:** заявка → проверка заполненности → результат

### Контракт

- **Вход:** заявка и заданный системой список обязательных полей.
- **Проверка:** одно детерминированное прохождение по списку. Предлагаю считать поле незаполненным, если его нет, оно равно `null` или содержит только пробелы.
- **Результат:** статус `complete` или `incomplete` и список незаполненных полей. Если вход нельзя разобрать как заявку, вернуть отдельный статус `invalid`.
- **Хранение:** только данные текущего вызова; состояние между заявками не сохраняется.
- **Завершение:** каждый вызов возвращает один результат. Повторных проверок и автоматических повторов нет.

### Проверка архитектуры

Все исходы завершаются результатом; ветвлений и циклов, способных зациклить выполнение, нет. Проверка локальная и детерминированная. Это архитектурный разбор, не результат тестирования кода.

**Проблема:** список обязательных полей пока не задан.  
**Критичность:** мешает определить, когда заявка заполнена.  
**Последствие:** одинаковые заявки могут получать разные результаты при разном составе полей проверки.  
**Рекомендация:** зафиксировать единый список обязательных полей и использовать его как правило проверки.

**Вердикт: требует доработки** — архитектура процесса определена, но состав обязательных полей ещё не согласован.
