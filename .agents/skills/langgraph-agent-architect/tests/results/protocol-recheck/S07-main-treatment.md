# S07-main-treatment

- Сценарий: `S7`
- Вариант: `treatment`
- Модель: `gpt-6-luna` (high)

## Ход 1 — запрос пользователя

У меня есть существующий LangGraph-граф, хочу обсудить его маршрутизацию.

## Ход 1 — ответ агента

Для обсуждения есть три режима:

- **Аудит** — оценить текущую маршрутизацию, найти проблемы и предложить улучшения.
- **Модификация** — продумать конкретное изменение в существующей маршрутизации.
- **Проектирование с нуля** — спроектировать новую схему маршрутов.

Я рекомендую **аудит**: вы хотите обсудить маршрутизацию уже существующего графа. В доступных файлах графа нет; когда выберете режим, пришлите его схему или описание маршрутов. Какой режим выбираете?

## Ход 2 — запрос пользователя

Выбираю режим «Аудит архитектуры». У узла `analyze` есть статический переход к `archive` и он может вернуть `Command(goto="review")`. Почему после analyze идут обе ветки?

## Ход 2 — ответ агента

Потому что `Command(goto="review")` **добавляет динамический маршрут**, но не отменяет статический `analyze → archive`. Поэтому после `analyze` запускаются обе ветки: `archive` и `review`.[Официальная инструкция LangGraph](https://raw.githubusercontent.com/langchain-ai/langchain-skills/main/config/skills/langgraph-fundamentals/SKILL.md)

Если узел должен выбирать только одно направление, уберите статический переход и задайте выбор одним механизмом маршрутизации. Я бы оставил `Command`, если `analyze` должен одновременно обновить состояние и выбрать следующий узел; для отдельной функции выбора подойдут условные переходы.
