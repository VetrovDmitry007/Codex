# S07-main-treatment

- Сценарий: `S7`
- Вариант: `treatment`
- Модель: `gpt-6-luna` (high)

## Ход 1 — запрос пользователя

У меня есть существующий LangGraph-граф, хочу обсудить его маршрутизацию.

## Ход 1 — ответ агента

Для LangGraph есть три режима:

- **Проектирование с нуля** — выбрать структуру нового графа.
- **Аудит архитектуры** — проверить существующий граф, найти проблемы маршрутизации и предложить улучшения.
- **Модификация архитектуры** — обсудить конкретные изменения в действующем графе.

По вашему описанию рекомендую **аудит архитектуры**: разберём текущие узлы, условия переходов и циклы, а затем оценим, где маршрутизация может вести к тупикам или неожиданным ветвлениям. Какой режим выбираете?

## Ход 2 — запрос пользователя

Выбираю режим «Аудит архитектуры». У узла `analyze` есть статический переход к `archive` и он может вернуть `Command(goto="review")`. Почему после analyze идут обе ветки?

## Ход 2 — ответ агента

Потому что статический `add_edge("analyze", "archive")` и `Command(goto="review")` — это два независимых указания маршрута. `Command` добавляет динамический переход, но не отменяет статический: LangGraph активирует `archive` и `review` на следующем шаге. [Документация LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api) прямо предупреждает, что при таком сочетании выполняются обе ветки.

Если `analyze` должен выбирать **одну** ветку, мой предпочтительный вариант — оставить выбор в `Command` и убрать статический переход к `archive`. Ограничение: это подходит, если сам узел принимает решение о маршруте; иначе выбор можно вынести в conditional edge.

Для этого фрагмента проблема ясна: маршрутизация не взаимоисключающая, поэтому неожиданно могут запуститься обе ветки. Полный вердикт по графу пока дать нельзя — я не видел остальных узлов и переходов. Вы ожидали, что `analyze` запускает только одну ветку?
