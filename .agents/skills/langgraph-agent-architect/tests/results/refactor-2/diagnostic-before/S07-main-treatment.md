# S07-main-treatment

- Сценарий: `S7`
- Вариант: `treatment`
- Модель: `gpt-6-luna` (high)

## Ход 1 — запрос пользователя

У меня есть существующий LangGraph-граф, хочу обсудить его маршрутизацию.

## Ход 1 — ответ агента

Для существующего графа есть три режима:

- **Аудит архитектуры** — разберём текущие маршруты, циклы и условия завершения; получим список проблем и рекомендаций.
- **Модификация архитектуры** — обсудим, как изменить маршрутизацию и какие контракты графа это затронет.
- **Проектирование с нуля** — подойдёт, если текущий граф нужно заменить новой архитектурой.

По вашему описанию я бы рекомендовал **аудит**, если цель — понять, хорошо ли устроена нынешняя маршрутизация. Какой режим выбираете?

## Ход 2 — запрос пользователя

Выбираю режим «Аудит архитектуры».

## Ход 2 — ответ агента

В рабочей папке нет материалов графа — только инструкции сессии. Поэтому пока не могу проверить его маршрутизацию. GitHub и другие удалённые сервисы в этой сессии использовать нельзя, так что аудит проведу по материалам, которые вы пришлёте сюда.

Пришлите фрагмент с объявлением графа (`StateGraph`, узлы, `add_edge` и `add_conditional_edges`), функции маршрутизации и ожидаемое поведение. Я рекомендую начать с этого кода: по нему можно восстановить достижимые пути и циклы, а затем проверить, где маршруты расходятся с ожиданиями.

## Ход 3 — запрос пользователя

У узла `analyze` есть статический переход к `archive` и он может вернуть `Command(goto="review")`. Почему после analyze идут обе ветки?

## Ход 3 — ответ агента

`Command(goto="review")` не отменяет статический переход. Поэтому `analyze` может направить выполнение и в `archive`, и в `review`; эти ветки могут пойти параллельно.

Если должен выбираться только один маршрут, уберите статический переход и оставьте маршрутизацию через `Command` — либо задайте оба варианта через условные переходы. Это моя рекомендация для взаимоисключающих веток. Если обе ветки должны выполняться, проверьте, как они объединяют изменения общего состояния.
