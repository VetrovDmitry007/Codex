## Ход 1 — запрос пользователя

У меня есть существующий LangGraph-граф, хочу обсудить его маршрутизацию.

## Ход 1 — ответ агента

Для существующего графа подходят три режима:

- **Аудит архитектуры** — проверю текущую маршрутизацию и дам замечания с рекомендациями.
- **Модификация архитектуры** — разберём, что стоит изменить в маршрутах, и согласуем обновлённую схему.
- **Проектирование с нуля** — предложу новую архитектуру графа.

Для начала рекомендую **аудит**: он поможет понять, как маршрутизация работает сейчас и где есть пространство для изменений. Какой режим выбираете?

## Ход 2 — запрос пользователя

Выбираю режим «Аудит архитектуры».

## Ход 2 — ответ агента

В рабочей папке нашлись только инструкции, кода графа нет, поэтому маршрутизацию пока проверить не могу. В GitHub есть [спецификация LangGraph от 2 ноября](https://github.com/VetrovDmitry007/Codex/blob/main/specs/langgraph-agent-architect-2026-11-02.md), но я не могу считать её описанием именно вашего графа.

Пришлите файл или фрагмент с узлами, функциями-роутерами, объявлениями рёбер и полями состояния, которые они используют. Рекомендую начать с этого участка: по нему можно предметно проверить достижимость веток и условия переходов.

## Ход 3 — запрос пользователя

У узла `analyze` есть статический переход к `archive` и он может вернуть `Command(goto="review")`. Почему после analyze идут обе ветки?

## Ход 3 — ответ агента

`add_edge("analyze", "archive")` — безусловный маршрут. `Command(goto="review")` добавляет к нему динамический переход, но не отменяет статическое ребро. Поэтому после `analyze` LangGraph планирует обе ветки: `archive` и `review`. Это поведение описано в [официальном руководстве LangGraph](https://github.com/langchain-ai/langchain-skills/blob/main/config/skills/langgraph-fundamentals/SKILL.md); справочники подтверждают, что `add_edge` задаёт переход, а `Command.goto` указывает узел назначения ([`add_edge`](https://reference.langchain.com/python/langgraph/graph/state/StateGraph/add_edge), [`Command`](https://reference.langchain.com/python/langgraph/types/Command)).

**Проблема:** статическое ребро и `Command` задают два исходящих маршрута из `analyze`.

**Критичность:** средняя, если ожидался выбор одной ветки; ниже, если обе должны запускаться.

**Последствие:** `archive` всё равно запустится вместе с `review`. Если обе ветки записывают в одно поле состояния или выполняют внешние действия, возможны конфликт обновлений или нежелательные побочные эффекты.

**Рекомендация:** если нужно выбрать одну ветку, уберите статическое ребро и направляйте `analyze` через `Command` в `review` или `archive`. Если архивирование должно идти после проверки, задайте последовательность `review → archive`.

**Вердикт:** для взаимоисключающей маршрутизации этот фрагмент **требует доработки**. Вывод относится только к описанным маршрутам; остальной граф не проверен.
