## Ход 1 — запрос пользователя

У меня есть существующий LangGraph-граф, хочу обсудить его маршрутизацию.

## Ход 1 — ответ агента

Использую навыки brainstorming и LangGraph Agent Architect. Для обсуждения маршрутизации есть три режима:

- **Аудит** — разберу текущие маршруты и отмечу проблемы и риски.
- **Модификация** — обсудим и согласуем изменения в существующей архитектуре.
- **Проектирование с нуля** — подготовим новую архитектуру.

Для начала рекомендую **аудит**: он покажет, как граф маршрутизирует сейчас и что стоит менять. Какой режим выбираете?

## Ход 3 — запрос пользователя

У узла `analyze` есть статический переход к `archive` и он может вернуть `Command(goto="review")`. Почему после analyze идут обе ветки?

## Ход 3 — ответ агента

`Command(goto="review")` не заменяет статические рёбра узла: он добавляет динамический переход. Поэтому `analyze` запускает и `archive` по `add_edge`, и `review` по `Command`. Это описанное поведение LangGraph [в официальном материале](https://github.com/langchain-ai/langchain-skills/blob/main/config/skills/langgraph-fundamentals/SKILL.md).

```mermaid
graph LR
  analyze -->|статическое ребро| archive
  analyze -->|Command(goto="review")| review
```

- **Проблема:** у `analyze` одновременно заданы статический и динамический маршруты.
- **Критичность:** средняя, если ветки должны быть взаимоисключающими; это может быть намеренным параллельным запуском, если нужны обе.
- **Последствие:** после `analyze` выполняются обе ветки.
- **Рекомендация:** если нужен ровно один маршрут, уберите статическое ребро к `archive` и задавайте назначение через `Command` для всех исходов `analyze`.
- **Вердикт:** **требует доработки** — для этого фрагмента не установлено, намерен ли параллельный запуск; остальной граф не проверен.

Должны ли `archive` и `review` быть взаимоисключающими маршрутами?
