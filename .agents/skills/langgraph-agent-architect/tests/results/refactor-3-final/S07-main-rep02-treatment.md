# S07-main-rep02-treatment

- Сценарий: `S7`
- Вариант: `treatment`
- Модель: `gpt-6-luna` (high)

## Ход 1 — запрос пользователя

У меня есть существующий LangGraph-граф, хочу обсудить его маршрутизацию.

## Ход 1 — ответ агента

Для существующего графа подходят три режима:

- **Проектирование с нуля** — разработать новую архитектуру и согласовать её спецификацию.
- **Аудит архитектуры** — проверить текущий граф, найти проблемы маршрутизации и предложить исправления.
- **Модификация архитектуры** — обсудить изменения в действующем графе и обновить его архитектурную спецификацию.

Рекомендую **аудит архитектуры**: вы хотите обсудить маршрутизацию уже существующего графа. Какой режим выбираете?

## Ход 2 — запрос пользователя

Выбираю режим «Аудит архитектуры».

## Ход 2 — ответ агента

В доступных материалах нет определения графа: в рабочей папке нашлись только `AGENTS.md` и `instructions/interaction-rules.md`. Поэтому пока нечего проследить и оценить.

Пришлите фрагмент с созданием графа, его узлами и рёбрами, функциями маршрутизации и используемыми ими полями состояния. Если есть конкретный маршрут, который ведёт себя не так, как ожидается, добавьте ожидаемый и фактический путь. Начать лучше с определения графа и связанных с ним маршрутизаторов; этого обычно хватает, чтобы проверить маршрутизацию без лишнего кода.

## Ход 3 — запрос пользователя

У узла `analyze` есть статический переход к `archive` и он может вернуть `Command(goto="review")`. Почему после analyze идут обе ветки?

## Ход 3 — ответ агента

`Command(goto="review")` не заменяет статические рёбра. Он добавляет динамический маршрут: из `analyze` LangGraph планирует и `archive` по статическому ребру, и `review` по `Command`. Поэтому запускаются обе ветки. Это описано в [документации LangGraph](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/graph-api.mdx).

**Проблема:** у `analyze` одновременно заданы статический и динамический маршруты; если это взаимоисключающие варианты, граф настроен противоречиво.

**Критичность:** средняя; высокая, если `archive` выполняет побочные действия.

**Последствие:** `archive` и `review` могут выполниться параллельно, хотя ожидался выбор одного пути.

**Рекомендация:** оставьте один механизм маршрутизации. Если `analyze` выбирает путь через `Command`, уберите ребро `analyze → archive`. Либо удалите `Command` и направляйте узел через условные рёбра.

**Вердикт:** для описанного фрагмента — **требует доработки**, если ветки должны быть альтернативами. Остальной граф не проверен.
