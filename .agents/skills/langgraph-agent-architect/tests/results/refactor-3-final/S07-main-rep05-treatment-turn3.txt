Потому что `Command(goto="review")` добавляет динамический маршрут, но не отменяет статический переход `analyze → archive`. LangGraph запускает обе ветки; обычно они становятся активными в одном следующем шаге и выполняются параллельно. Это прямо описано в [официальной документации LangGraph](https://docs.langchain.com/oss/python/langgraph/graph-api#command).

```mermaid
graph LR
    analyze -->|статический edge| archive
    analyze -->|Command(goto="review")| review
```

Если `archive` должен запускаться всегда, а `review` — только по условию, опишите оба маршрута одним механизмом: например, условной маршрутизацией, которая возвращает `archive` либо `archive` и `review`. Если нужен ровно один маршрут, выбирайте между `archive` и `review`. Не смешивайте статический edge и `Command` для маршрутизации из одного узла.

**Проблема:** у `analyze` одновременно заданы статический и динамический маршруты.

**Критичность:** средняя; оба узла запускаются, даже если ожидался только один.

**Последствие:** `archive` выполняется вместе с `review`; если обе ветки обновляют одни и те же поля состояния, могут возникнуть конфликты записи.

**Рекомендация:** выбрать одно средство маршрутизации и явно выразить им, должна ли `archive` запускаться всегда или только вместо `review`.

**Вердикт:** **требует доработки** для описанного фрагмента. Остальные узлы и обновления состояния не проверялись.
