# S07-main-rep02-treatment

- Сценарий: `S7`
- Вариант: `treatment`
- Модель: `gpt-6-luna` (high)

## Ход 1 — запрос пользователя

У меня есть существующий LangGraph-граф, хочу обсудить его маршрутизацию.

## Ход 1 — ответ агента

Для обсуждения маршрутизации выберите режим:

- **Аудит архитектуры** — разберём существующие маршруты, условия переходов и возможные тупики.
- **Модификация архитектуры** — обсудим, как изменить маршрутизацию графа.
- **Проектирование с нуля** — спроектируем новую архитектуру маршрутизации.

Рекомендую **аудит архитектуры**, поскольку у вас уже есть граф. Какой режим выбираете?

## Ход 2 — запрос пользователя

Выбираю режим «Аудит архитектуры».

## Ход 2 — ответ агента

В рабочей папке графа нет: доступны только `AGENTS.md` и правила взаимодействия. Чтобы проверить маршрутизацию, пришлите фрагмент с объявлениями узлов, функциями выбора маршрута, рёбрами и связанными полями состояния; мой предпочтительный вариант — ограничиться участком вокруг маршрута, который вызывает вопросы, и я обозначу границы такого аудита.

## Ход 3 — запрос пользователя

У узла `analyze` есть статический переход к `archive` и он может вернуть `Command(goto="review")`. Почему после analyze идут обе ветки?

## Ход 3 — ответ агента

`Command(goto="review")` добавляет динамический переход, но не отменяет статическое ребро `analyze → archive`. Поэтому после `analyze` граф запускает **обе ветки**; это не выбор одного маршрута. [Документация LangGraph](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/graph-api.mdx)

```mermaid
flowchart LR
  analyze -->|статическое ребро| archive
  analyze -.->|Command(goto="review")| review
```

**Проблема:** по вашему описанию у `analyze` одновременно заданы статический и динамический переходы. Проверен только этот фрагмент; остальной граф неизвестен.

**Критичность:** средняя, если ожидался выбор одной ветки; обе ветки могут выполнить работу.

**Последствие:** `archive` и `review` запустятся как отдельные задачи. Если они пишут в одни поля состояния, результат также зависит от правил объединения этих обновлений.

**Рекомендация:** для выбора одного следующего узла оставьте один механизм маршрутизации: например, удалите статический переход и выбирайте `archive` или `review` через `Command`. Если `archive` должен выполняться всегда, а `review` — после него, задайте это как последовательность с отдельным условным переходом.

**Вердикт:** `требует доработки`, если предполагается взаимоисключающий маршрут от `analyze`; вердикт касается только описанного фрагмента.
