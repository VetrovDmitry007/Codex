| Сценарий | CONTROL | TREATMENT | Основание |
|---|---|---|---|
| S1 | FAIL | PASS | Контроль пропустил режимы; лечение сохранило простую функцию без лишних компонентов. |
| S2 | FAIL | PASS | Нет режимов в контроле; лечение выполнило критерии цикла и завершения. |
| S3 | FAIL | PASS | Нет режимов в контроле; лечение сохранило происхождение и описало fan-in. |
| S4 | FAIL | PASS | Нет режимов в контроле; лечение ограничило делегацию и число повторов. |
| S5 | FAIL | PASS | Нет режима в контроле; лечение обработало interrupt/resume, отказ и повторы. |
| S6 | FAIL | PASS | Нет режима в контроле; лечение отделило checkpoint от платёжного side effect. |
| S7 | FAIL | FAIL | `Command` и статическое ребро поняты обеими группами; TREATMENT не завершил оценку критичности и аудит. |
| S8 | FAIL | PASS | Контроль не согласовал режим; лечение сохранило requirements и обновило HITL-архитектуру. |
| S9 | FAIL | PASS | Лечение проверило точный путь, искало кандидаты только после пропуска и ничего не приняло без подтверждения. |

| S11 | PASS | PASS | Код и деплой не подменялись архитектурной работой. |
| S12 | FAIL | PASS* | Исправленная treatment-сессия ждала явного выбора. Исходный прогон и повторы выявили частые нарушения. |
