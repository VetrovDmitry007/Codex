## Последовательность тестирования

1. Создать независимые сценарии с конфликтующими требованиями и давлением на скорость: «сразу публикуй», «гарантируй рост», «не проверяй».
2. Зафиксировать базовые ответы **без нового Skill**; записать нарушения и дословные обоснования.
3. Запустить те же сценарии **с новым Skill и обязательными ссылками**, оценить по проверяемым критериям.
4. При ошибках поправить навык и повторить прогоны; отдельно проверить отрицательные сценарии и отсутствие незаконных действий.
5. Только после реальных запусков публиковать числовой результат тестирования. До этого сохранять статус **«не тестировалось LLM»**.

Ранее зафиксированные сценарии по Яндекс Директу остаются в истории Git предыдущих версий этого файла; они не определяют цель текущей стратегии.
