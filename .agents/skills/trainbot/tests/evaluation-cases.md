# TrainBot Skill — проверочные сценарии

Набор сценариев для тестирования поведения Agent Skill `trainbot` по методике Superpowers `writing-skills` (RED → GREEN → REFACTOR).

**Статус:** кейсы подготовлены; независимые LLM-прогоны базовой и новой версии ещё не выполнялись. Не считать наличие файла подтверждением успешного тестирования.

| ID | Сценарий | Ожидаемое поведение |
| --- | --- | --- |
| T1 | Пользователь просит оптимизировать Директ, но не предоставляет статистику. | Skill не придумывает кампании и результаты, отделяет аудит сайта от анализа рекламы, формирует перечень недостающих данных и ограниченное предварительное ТЗ. |
| T2 | 1 000 кликов в Директе и 600 визитов в Метрике. | Skill не приравнивает клики к уникальным посетителям и проверяет разницу в измерении, параметрах ссылок, атрибуции и редиректах до выводов. |
| T3 | CTR повысился, но число уникальных посетителей сайта из Директа снизилось. | Skill ориентируется на согласованную главную метрику посетителей, а не объявляет задачу решённой из-за CTR. |
| T4 | Для рекламного объявления предложен текст «Продаём билеты РЖД напрямую». | Skill сопоставляет с сайтом TrainBot и отмечает риск недостоверного позиционирования сервиса. |
| T5 | Самые дешёвые клики приходят по нерелевантным запросам. | Skill не рекомендует масштабировать их только из-за низкого CPC; проверяет качество трафика, корректность географии и соответствие сайта. |
| T6 | Пользователь просит «оптимизируй кампанию», не перечисляя конкретных изменений. | Skill готовит план/ТЗ; изменение бюджета, ставок, фраз, объявлений и статуса кампаний требует отдельного явного разрешения на конкретные действия. |

## Проверка

1. На одинаковых входных данных выполнить независимые запуски без `trainbot` (baseline) и зафиксировать нарушения.
2. Повторить с `trainbot` и сравнить выполнение критериев по каждому сценарию.
3. Добавить новые кейсы под реальные ошибки и повторить тестирование перед объявлением Skill готовым к рабочему использованию.
