# Частное развёртывание SearXNG

Этот каталог содержит конфигурацию для отдельного Compose-проекта `bondnav-searxng`. Она собирает собственный образ из `source/SearXNG` и публикует контейнерный порт `8080` только на `127.0.0.1:8088`. Compose не запускает Valkey или Redis.

## Подготовка сервера

Развёртывание по исходной задаче размещается в `/home/kasper/data/sear_xng`. До копирования проверьте доступ к серверу, наличие Docker Compose v2, свободное место и отсутствие конфликта на loopback-порту 8088. Не меняйте настройки чужих контейнеров, SSH или firewall.

В каталоге установки используйте следующую структуру:

```text
sear_xng/
├── docker-compose.yml
├── .env
├── config/settings.yml
├── config/private-entrypoint.sh
├── secrets/searxng_secret
├── data/
└── source/SearXNG/   # checkout пользовательского репозитория на проверенном SHA
```

Скопируйте `docker-compose.yml`, `settings.yml` и `private-entrypoint.sh` из этого каталога соответственно в корень установки, `config/settings.yml` и `config/private-entrypoint.sh`. Скопируйте `.env.example` в `.env`. Заполните полный SHA проверенного коммита, короткий SHA и время сборки в UTC. Секрет создайте непосредственно на сервере отдельным Compose secret-файлом, например:

```sh
umask 077
mkdir -p secrets
python3 -c 'import secrets; print(secrets.token_urlsafe(48))' > secrets/searxng_secret
chmod 600 secrets/searxng_secret
```

Обёртка читает secret-файл при старте и передаёт значение штатному entrypoint SearXNG через переменную `SEARXNG_SECRET`. Само значение не хранится в `.env`, Compose YAML, выводе `docker compose config`, логах или README. Не добавляйте `.env` и каталог `secrets/` в Git. Установите права доступа к `.env`, `secrets/` и каталогу `config` так, чтобы посторонние пользователи не могли их прочитать или изменить.

## Сборка и управление

Проверьте значения `.env`, затем из `/home/kasper/data/sear_xng` выполните:

```sh
docker compose config --quiet
docker compose build --pull
docker compose up -d
docker compose ps
docker compose logs --tail=100 searxng
```

Исходники приложения берутся из локального checkout `source/SearXNG`. В `container/Dockerfile` оба базовых образа SearXNG Base закреплены OCI digest, поэтому изменения плавающих тегов не меняют базовые слои сборки. Перед обновлением исходников зафиксируйте полный SHA репозитория, проверьте Compose-конфигурацию и выполните сборку. Не используйте плавающий upstream-образ SearXNG в качестве образа приложения.

Проверить HTML и JSON API можно с самого сервера:

```sh
curl -fsS http://127.0.0.1:8088/ -o /dev/null
curl -fsS --get http://127.0.0.1:8088/search \
  --data-urlencode 'q=BondNavigator' --data-urlencode 'format=json'
```

Для клиента с доступом через существующий SSH-шлюз создайте туннель на адрес сервера, например `ssh -L 8088:127.0.0.1:8088 <пользователь>@<сервер>`, после чего откройте `http://127.0.0.1:8088/` на клиенте. Не добавляйте публичную публикацию порта.

Остановить или перезапустить только этот проект:

```sh
docker compose restart searxng
docker compose down
```

Не добавляйте `-v` к `down`: данные и конфигурация хранятся в каталогах `config/` и `data/`.

## Резервирование, восстановление и откат

Для резервной копии остановите только этот сервис либо согласуйте консистентный снимок каталогов `config/` и `data/`. Храните `.env` и резервную копию файла `secrets/searxng_secret` отдельно и с ограниченными правами. Для восстановления разверните исходники нужного проверенного SHA, восстановите каталоги и файлы секрета, затем выполните проверку конфигурации, сборку, `up -d` и HTTP-проверки.

Для отката верните checkout на предыдущий проверенный SHA и его `SEARXNG_TAG`/`SEARXNG_REVISION`, пересоберите образ и перезапустите этот Compose-проект. Сохраните конфигурацию и данные, пока не подтверждено успешное восстановление.

После фактического развёртывания дополните серверный README проверенным SHA, версиями Docker/Compose, командами и результатами проверок UI, JSON API, loopback-bind, SSH-туннеля, перезапуска и отсутствия Valkey/Redis. Не записывайте в документацию секреты.
