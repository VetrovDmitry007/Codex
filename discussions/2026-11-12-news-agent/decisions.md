## История решений

### 2026-11-12 — Пункт 01: исключение PDF

**Статус: полностью согласовано; реализация не начата.**

Согласовано изменить только слой `data_sources/additional_news`:

1. В `service.py` отфильтровывать URL, чей путь заканчивается на `.pdf` без учёта регистра (query и fragment не влияют), **до** дедупликации по домену. PDF не должен занимать слот HTML-статьи с того же сайта.
2. В `reader.py` проверять URL до GET при прямом вызове `read_sources`; каждый адрес перенаправления проверять до следующего GET.
3. Если сервер возвращает `Content-Type: application/pdf` или заголовок `Content-Disposition` явно указывает PDF, прекращать обработку **до чтения тела**. Для PDF по URL без расширения начальный запрос заголовков неизбежен.
4. Исключённые PDF не включать в `sources`, не передавать в `prepare_sources` и `analyze_result`, не считать технической ошибкой. Добавить агрегированное количество пропусков в лог.
5. Сохранить публичные контракты `AdditionalSearchResult`, `AdditionalSource`, `search_additional_news`, лимит пяти успешно загруженных HTML-источников и существующую обработку остальных HTTP-ошибок. Другие расширения (`.docx`, `.xlsx`) не входят в задачу.

**Приёмка:** тесты на `.pdf`, `.PDF`, query и fragment, PDF-редирект, PDF MIME, `Content-Disposition` и HTML-страницу с того же домена; для очевидного PDF URL GET не выполняется, для PDF MIME тело ответа не читается. После реализации запустить `pytest` и зафиксировать результат.

**Отдельное разрешение на изменение кода пока не дано.**
