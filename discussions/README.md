# Обсуждения и согласование изменений

Этот каталог предназначен для рабочих обсуждений улучшений проектов, прежде чем они превратятся в окончательные спецификации и планы реализации.

## Структура

Каждая тема хранится в собственном каталоге с именем `YYYY-MM-DD-topic`, например [2026-11-12-news-agent](2026-11-12-news-agent/).

- `proposals.md` — исходные предложения, предположения, критерии и вопросы. Наличие пункта не означает его утверждение.
- `decisions.md` — журнал явно согласованных решений с датой, статусом и ссылкой на соответствующий пункт.

## Порядок работы

1. Обсуждать один вопрос за раз.
2. Записывать решение только после явного согласования; не подменять решение рекомендацией.
3. При пересмотре решения сохранять краткую историю изменения.
4. До правки перечитывать актуальный файл в GitHub и обновлять точечно.
5. После завершения обсуждения оформлять техническую спецификацию или план реализации в [`specs/`](../specs/); рабочее обсуждение сохранять как историю.

Файлы обсуждения не являются разрешением менять код. Не сохранять API-ключи, токены, приватные журналы или другие секреты.
