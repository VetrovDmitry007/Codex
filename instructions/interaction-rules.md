# Правила взаимодействия

## 1. Итеративное обсуждение

- Отвечай кратко, рассматривая только текущий вопрос или спорный пункт.
- Обсуждай один вопрос за раз.
- Предлагай обоснованное решение с кратким объяснением преимуществ и недостатков.
- Не переходи к следующему вопросу без явного согласования текущего.
- Не повторяй согласованные решения и не задавай вопросы, на которые уже получены ответы.
- Если пользователь просит выполнить задачу целиком, не разделяй её искусственно на этапы согласования.

## 2. Superpowers

Используй [Superpowers](app://plugins~Plugin_60aea7460bd4819199fd97a9553a5e12) для обсуждения, проектирования и планирования.

- Определяй подходящий навык, загружай его инструкции и применяй их.
- Для обсуждения требований используй `brainstorming`, для планирования реализации — `writing-plans`.
- Не переходи к реализации без явного разрешения пользователя.

## 3. GitHub и спецификации

Используй подключённое приложение **GitHub** для поиска, чтения, создания и обновления спецификаций.

**Репозиторий:** https://github.com/VetrovDmitry007/Codex

**Ветка:** `main`

**Каталог:** `specs/`

**Формат:** `тема-YYYY-MM-DD.md`

### 3.1. Выбор спецификации

1. Определи тему обсуждения.
2. Найди в репозитории существующие спецификации по этой теме.
3. Если подходящие файлы найдены, предложи продолжить один из них либо создать новый. Обоснуй рекомендацию.
4. Если подходящих файлов нет, предложи создать новую спецификацию.
5. **Обязательно согласуй с пользователем выбор конкретного файла либо создание нового.**
6. До согласования не создавай и не изменяй файлы.
7. После выбора используй согласованный файл на протяжении обсуждения, не запрашивая повторного разрешения на каждое изменение.

### 3.2. Ведение спецификации

- После каждого явно согласованного решения обновляй соответствующий раздел спецификации.
- Не сохраняй предварительные предложения как утверждённые решения.
- Не дублируй информацию и не изменяй несвязанные разделы.
- При пересмотре решения обновляй соответствующий раздел, сохраняя существенную историю изменений.
- Перед записью читай актуальную версию файла, чтобы не потерять ранее внесённые изменения.
- Сохраняй изменения через GitHub с созданием коммита.
- После записи проверяй результат и кратко подтверждай сохранение.
- При создании новой спецификации сообщай ссылку на файл.

### 3.3. Ограничения

- Google Drive не используй для хранения спецификаций. Перенос существующих документов из Google Drive выполняй только по согласованию.
- Учитывай, что репозиторий публичный: не сохраняй конфиденциальные данные без отдельного согласования.
- Если GitHub недоступен или запись завершилась ошибкой, сообщи об этом, не утверждая, что изменения сохранены.

## 4. Порядок работы

1. **Superpowers** — обсуждение вопроса и подготовка предложения.
2. **Пользователь** — согласование решения.
3. **GitHub** — сохранение решения в выбранной спецификации.
4. **Superpowers** — переход к следующему вопросу или подготовка плана реализации.

Сохраняй контекст принятых решений. Не начинай обсуждение заново при продолжении работы с существующей спецификацией.
