# Правила взаимодействия — SEO и Яндекс Директ для TrainBot

> Специализированная инструкция для исследования проблем продвижения https://trainbot.ru/, подготовки спецификаций, дорожных карт и технических заданий. Применяется **вместо общих правил** `instructions/interaction-rules.md` при работе над продвижением TrainBot; общие принципы согласования и работы с GitHub сохраняются. Это **точка входа в работу над задачами**, а не замена специализированного Skill.

## 1. Цель и распределение ответственности

**Согласованная главная цель проекта:** максимизировать количество **уникальных посетителей trainbot.ru из Яндекс Директа** в пределах согласованного рекламного бюджета и ограничений.

Не подменяй посетителей кликами, визитами, показами, CTR или переходами в Telegram. Переходы в бот и качество трафика — дополнительные диагностические показатели.

Термины **SEO** (органический поиск, техническая и контентная оптимизация сайта) и **Яндекс Директ** (платная реклама) различай. Если задача касается органического SEO, обозначь отдельную цель, метрики и влияние на общую стратегию; не приписывай SEO-работам прямое увеличение трафика из Директа без обоснования. Для посадочных страниц, рекламной семантики и UX исследуй взаимосвязь обоих направлений.

Для каждой задачи используй совместно:

- **[Superpowers](app://plugins~Plugin_60aea7460bd4819199fd97a9553a5e12)** — обсуждение требований, сравнение решений, согласование спецификации и планирование. При проектировании используй `brainstorming`, после утверждения дизайна — `writing-plans`; для создания/изменения Skill — `writing-skills`. Перед применением изучай актуальные инструкции навыков.
- **[Специализированный Skill `trainbot`](../.agents/skills/trainbot/SKILL.md)** — **обязательный профильный навык** для анализа TrainBot, доказательной диагностики рекламы, сайта и подготовки ТЗ. **Прочитай актуальный `SKILL.md` целиком**, затем его обязательные справочники: [профиль сайта](../.agents/skills/trainbot/references/verified-site-profile.md) и [методику SEO/PPC](../.agents/skills/trainbot/references/yandex-direct-methodology.md). Не заменяй Skill пересказом из этой инструкции.
- **GitHub** — единственный источник актуальных согласованных спецификаций и дорожных карт, а также место сохранения новых решений. Репозиторий: https://github.com/VetrovDmitry007/Codex, ветка `main`.
- **Специализированные SEO/PPC методики** — через ссылки и правила `trainbot`: `Silverov/yandex-direct-skill`, `Horosheff/google-yandex-seo-skill`, `coreyhaines31/marketingskills`. Это внешние справочники, а не автоматически подключённые инструменты. Актуальные правила платформ сверяй с официальными источниками Яндекса.

Если Skill недоступен, явно укажи ограничение. Не заявляй об использовании инструмента, который не был прочитан или запущен; запроси доступ к отсутствующим материалам только тогда, когда без них нельзя выполнить задачу.

## 2. Режимы работы

Определи режим по запросу пользователя; **если он уже однозначно задан, не переспрашивай**. При неоднозначности предложи подходящий вариант и спроси согласие:

1. **Исследование и аудит** — проверка сайта, посадочных страниц, рекламного кабинета, аналитики, поисковых запросов; поиск подтверждённых проблем и гипотез.
2. **Проектирование решения** — формирование новой спецификации оптимизации для определённой проблемы или цели.
3. **Дорожная карта** — приоритизация нескольких согласованных задач по зависимостям, эффекту, трудозатратам, рискам и проверкам.
4. **Модификация существующей спецификации / дорожной карты** — обновление ранее согласованного решения после появления новых данных.

Если пользователь просит только аудит, не создавай дорожную карту без запроса. Если он просит сразу итоговое ТЗ или дорожную карту, выполни всю доступную часть, не навязывая лишние промежуточные этапы.

## 3. Источники фактов и доказательств

Перед рекомендациями:

1. Прочитай `trainbot` и его профиль сайта. Проверяй изменяемые сведения (цены, условия, гарантии, функции, путь в Telegram) по актуальному сайту/боту или подтверждению владельца. **Опубликованное обещание ≠ доказанная гарантия.** TrainBot — сервис поиска/отслеживания/бронирования, а не официальная касса РЖД.
2. Сначала посмотри уже предоставленные материалы, спецификации, ранее принятые решения. Не спрашивай данные повторно.
3. Для рекламы используй по доступности данные Яндекс Директа: кампании, настройки, расходы, показы, клики, поисковые запросы, сети, история изменений; для трафика — Метрику, атрибуцию, посетителей, источники и качество измерения; для спроса — Вордстат. При отсутствии доступа допускаются предоставленные пользователем выгрузки. Ничего не выдумывай.
4. Для SEO проверяй реальные страницы, индексацию, техническое состояние, релевантность поисковому намерению, мобильный путь и понятность предложения. Не объявляй проблему подтверждённой, если проверка не состоялась.
5. К каждому существенному выводу приводи **источник, дату/период, наблюдаемые данные и степень достоверности**; отдельно отмечай **факты, гипотезы, недостающие данные (MISSING)**.

При отсутствии достоверных данных разрешён предварительный аудит и план измерений, но не категоричные рекомендации менять ставки, отключать фразы или расширять бюджет. Универсальные «нормы CTR/CPC/CPA» и оценки сторонних Skills не использовать как доказательство проблемы.

## 4. Обсуждение и выбор решения

- Общайся кратко, **один спорный вопрос за раз**. После каждого вопроса предложи свой предпочтительный вариант с обоснованием, пользой и ограничениями.
- Формулируй проблему как **факт → вероятная причина → проверка → варианты решения → рекомендованный выбор**.
- Если есть несколько разумных подходов, сравни их. Не создавай искусственные альтернативы.
- Не переходи к следующему требующему выбора решению без согласования текущего. Не объявляй гипотезы согласованными требованиями.
- Superpowers управляет процессом обсуждения и проектирования, `trainbot` предоставляет предметную методику.
- После утверждения решения фиксируй его в согласованной спецификации. Изменение рекламного кабинета или сайта — **отдельный этап, требующий явного разрешения**.

## 5. Спецификация задачи

Спецификация предназначена для **одной проблемы или логически связанного набора изменений**; её содержание соразмерно масштабу работы. Предпочтительные разделы:

1. **Контекст и цель:** проблема, её связь с привлечением посетителей, объект (URL, кампания, группа, объявление) и границы.
2. **Исходное состояние:** проверенные факты, показатели, период, источники, ограничения и `MISSING`.
3. **Диагноз:** подтверждённая причина или проверяемые гипотезы; альтернативные объяснения и риски ошибок измерения.
4. **Варианты решения:** достоинства, ограничения и рекомендуемый вариант.
5. **Согласованное решение:** конкретные изменения, затрагиваемые объекты, требования и то, что **не** меняется.
6. **Критерии приёмки:** проверяемые технические и маркетинговые результаты; основной KPI — уникальные посетители из Директа, если задача относится к платному трафику.
7. **Проверка эффекта:** исходный уровень, сравнимый период, модель атрибуции, условия эксперимента/отката.
8. **Статус решений:** согласовано / гипотеза / ожидает данные / отложено.

Не утверждай, что изменение гарантированно увеличит трафик. Для чисто органических SEO-задач используй собственные метрики поиска и не смешивай их с показателями Директа.

## 6. Дорожная карта

Дорожную карту составляй **на основе согласованных проблем и спецификаций**, указывая для каждого пункта:

- ссылку на исходную спецификацию, объект и ожидаемый результат;
- приоритет (**P0** — ошибка измерения или критический блокер; **P1** — подтверждённое существенное улучшение; **P2** — эксперимент);
- подтверждение проблемы / гипотезу / недостающие данные;
- зависимость от других задач, этап, ответственного (если известен);
- оценку эффекта с допущениями, риски, трудозатраты (если есть основания);
- критерий завершения и способ последующего измерения.

**Сначала валидность измерения, затем доказательная диагностика, затем вмешательства и контроль эффекта.** Не выдавай набор общих SEO-пожеланий за дорожную карту. Не оценивай сроки и экономический эффект как факт при отсутствии данных.

## 7. GitHub: выбор и ведение документов

**Репозиторий:** `VetrovDmitry007/Codex`; **ветка:** `main`; **каталог:** `specs/`.

- Для задач продвижения TrainBot предпочитай тематический каталог `specs/trainbot/`, если нет согласованного иного места; перед использованием проверь, существует ли он, и найди связанные документы.
- **До создания нового файла** изучи имеющиеся спецификации по теме и **согласуй с пользователем конкретный файл**: продолжить существующий или создать новый. Если пользователь прямо указал путь/файл — сначала читай его, не подменяй другим.
- После выбора веди **одну каноническую спецификацию**, а для комплексной программы — одну каноническую дорожную карту со ссылками на спецификации. Не создавай дубликаты «на всякий случай».
- Рекомендуемые имена внутри тематического каталога: `spec-YYYY-MM-DD.md`, `roadmap-YYYY-MM-DD.md`, `task-YYYY-MM-DD.md`; если в каталоге уже есть такие файлы, используй уточняющее короткое имя или существующий согласованный.
- `superpowers:writing-plans` используй для планирования **после утверждения спецификации**, сохраняя план рядом с ней, а не параллельно в `docs/superpowers/plans/`. Если план нужен, файл может называться `plan-YYYY-MM-DD.md`.
- Сохраняй **только утверждённые решения**; гипотезы помечай соответствующим статусом. После каждого согласования обновляй выбранный документ, предварительно прочитав его актуальную версию.
- Используй подключённый GitHub для коммита, **проверяй запись повторным чтением** и сообщай ссылку. Не используй Google Drive для хранения спецификаций.
- Репозиторий публичный: **не сохраняй** API-токены, приватные выгрузки Директа/Метрики, секреты или персональные данные без отдельного явного согласования и проверки безопасного формата публикации.

## 8. Проверка результата и границы полномочий

Перед передачей спецификации/дорожной карты проверь по `trainbot`:

1. Решения относятся к реальным возможностям сайта и актуальным правилам Яндекса.
2. Каждое действие обосновано данными либо явно маркировано как эксперимент.
3. Не смешаны органические и рекламные показатели, клики/визиты/посетители.
4. Техническое задание реализуемо и содержит критерии проверки и риски.
5. Согласованные решения отделены от открытых вопросов.

**По умолчанию выполняй только исследование, обсуждение и подготовку документов.** Не меняй объявления, кампании, ставки, бюджет, цели Метрики, код или страницы сайта без отдельного разрешения с перечислением конкретных изменений. При ошибке источника или GitHub честно сообщай о неполноте работы.

## 9. Порядок совместной работы

**Superpowers + `trainbot` → проверка источников → обсуждение и согласование → GitHub-спецификация → дорожная карта (при необходимости) → явное разрешение на реализацию → измерение результата.**

При продолжении работы сначала читай выбранные документы и историю решений; не начинай согласование заново.
