# TrainBot — правила разработки специализированного Skill

## Назначение

Разработать специализированный Agent Skill `trainbot` для анализа сайта https://trainbot.ru/ и подготовки обоснованных заданий по оптимизации рекламы в Яндекс Директе.

**Главная цель:** максимизировать число посетителей сайта, привлечённых из Яндекс Директа, в рамках бюджета и ограничений, которые будут определены в спецификации. Не подменять цель количеством кликов: различать клики, визиты и посетителей, проверять измерение в Метрике. SEO — вспомогательный инструмент анализа сайта и посадочных страниц, а не самостоятельная цель проекта.

**Специализированный Skill:** [`trainbot`](../.agents/skills/trainbot/SKILL.md) — основной рабочий навык для анализа TrainBot и подготовки заданий на оптимизацию Яндекс Директа.

**Рабочий каталог Skill:** `.agents/skills/trainbot/`.

**Обязательные материалы Skill:** [`references/verified-site-profile.md`](../.agents/skills/trainbot/references/verified-site-profile.md) (проверенные факты официального сайта, источник и свежесть) и [`references/yandex-direct-methodology.md`](../.agents/skills/trainbot/references/yandex-direct-methodology.md) (адаптация методик SEO/Яндекс Директа к цели посещаемости). Перед подготовкой каждого ТЗ считывать оба файла и проверять изменяемые условия по актуальным источникам.

**Каталог спецификаций:** `specs/` (имя файла и его создание согласовывать по `instructions/interaction-rules.md`).

## Обязательные инструменты и навыки

### 1. Superpowers — обсуждение, проектирование и проверка

Использовать установленный набор навыков **Superpowers**:
- `brainstorming` — выяснение требований, вариантов решения и согласование архитектуры до реализации;
- `writing-plans` — пошаговый план реализации после утверждения спецификации;
- `writing-skills` — разработка, структура и тестирование `SKILL.md`;
- `test-driven-development` и `verification-before-completion` — проверка поведения Skill на сценариях и подтверждение результата.

Перед применением читать актуальные инструкции соответствующего навыка, а не полагаться на пересказ. Разрабатывать итеративно; решения, требующие выбора, согласовывать с пользователем. Первичная версия `SKILL.md` создана по прямому запросу пользователя. Новые функции и изменения правил Skill предварительно согласовывать; проверять с помощью `writing-skills` и тестовых сценариев.

### 2. GitHub — источник и хранилище рабочих материалов

Использовать подключённый инструмент **GitHub** для чтения, создания и обновления файлов в репозитории:

- Репозиторий: https://github.com/VetrovDmitry007/Codex
- Ветка по умолчанию: `main`
- Инструкции: `instructions/`
- Спецификации: `specs/`
- Разрабатываемый Skill: `.agents/skills/trainbot/`

Перед изменением читать актуальную версию затрагиваемых файлов. Сохранять согласованные решения коммитами; после записи проверять содержимое. Соблюдать общие правила из `instructions/interaction-rules.md`. Не добавлять в публичный репозиторий токены API, персональные данные, конфиденциальную статистику или доступы.

### 3. Специализированные SEO / рекламные Skills — источники методик

Изучить релевантные инструкции и приемы следующих **внешних проектов**, прежде чем формировать собственные правила. Они не считаются автоматически установленными или подключёнными навыками.

| Проект | Для чего использовать |
| --- | --- |
| [Silverov/yandex-direct-skill](https://github.com/Silverov/yandex-direct-skill) | Анализ кампаний Яндекс Директа, отчетов, поисковых фраз и настроек рекламного кабинета. |
| [Horosheff/google-yandex-seo-skill](https://github.com/Horosheff/google-yandex-seo-skill) | Технический SEO-аудит, соответствие сайта запросам и качество посадочных страниц с учётом Яндекса. |
| [coreyhaines31/marketingskills](https://github.com/coreyhaines31/marketingskills) | Организация маркетингового контекста, paid ads, аудит конверсий и гипотезы улучшений. |

При заимствовании решений проверять актуальные исходные файлы, лицензии и применимость к Яндекс Директу. Не копировать сторонние Skills целиком без необходимости; использовать их как специализированные справочники и составлять собственную логику под TrainBot. При расхождении с актуальной официальной документацией Яндекса приоритет имеет документация Яндекса.

## Порядок работы

1. Изучить реальное содержание сайта TrainBot; отдельно зафиксировать проверенные факты и неподтверждённые предположения.
2. Согласовать спецификацию продукта, целевой аудитории, целей измерения трафика, бюджета и ограничений. Не придумывать показатели.
3. Исследовать специализированные Skills и официальные возможности Яндекс Директа, Метрики и Вордстата, применимые к согласованной задаче.
4. С помощью Superpowers спроектировать `trainbot`, согласовать спецификацию и план.
5. Разработать и протестировать Skill на воспроизводимых сценариях, включая нехватку данных и риск ложных выводов.
6. Результат работы Skill — приоритизированное **задание на оптимизацию рекламы** с фактами, источниками данных, ожидаемым влиянием, рисками и критериями проверки. Изменять рекламные кампании без отдельного разрешения нельзя.

## Правила взаимодействия

Следовать `instructions/interaction-rules.md`: короткие итерации, один обсуждаемый вопрос за раз, рекомендация с обоснованием, фиксация только согласованных решений. Не выдавать рабочие предположения за утверждённые требования.
