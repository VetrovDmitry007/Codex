# Слой поиска дополнительных новостей `data_sources/additional_news` — архитектурная спецификация

**Проект:** BondNavigator  
**Компонент:** `data_sources/additional_news`  
**Дата начала:** 2026-11-07  
**Статус:** черновик; записаны согласованные решения, открытые вопросы отмечены отдельно. Программный код не изменён.

**Спецификация потребителя:** [контракт отдельной LangGraph-ноды `additional_search`](../analysis_news/additional-search-node-2026-11-07.md). Граф, `AgentState`, `SourceData`, суммаризация, валидация и маршрутизация находятся **только в спецификации интеграции**, не в этом документе. Нода `additional_search()` напрямую вызывает публичную функцию сервиса `search_additional_news(fact, query)` без инструментальной обёртки.

## 1. Назначение и границы

Создать независимый от LangGraph пакет получения **дополнительных публикаций** для проверки факта о конкретном эмитенте. Слой принимает проверяемое утверждение и готовый поисковый запрос, сформированный вызывающей LLM, ищет источники через MCP SearXNG, выбирает подходящие публикации, самостоятельно получает их **полные тексты** и возвращает структурированные данные и диагностические сообщения.

В пакет **не входят** LLM-суммаризация, экспертная оценка достоверности факта, управление состоянием графа и маршрутизация агента. Эти функции реализует потребитель. Пакет должен быть пригоден для вызова из других частей проекта и для ручного тестирования без LangGraph.

## 2. Архитектура файлов

```text
data_sources/
└── additional_news/
    ├── config.py                 # SEARXNG_MCP_URL, MCP_TIMEOUT = 30, DOWNLOAD_CONCURRENCY = 1, MAX_HTML_SIZE_BYTES.
    ├── models.py                 # Модели публикаций и результата поиска.
    ├── service.py                # Публичная функция и оркестрация, сбор AdditionalSearchResult.
    ├── reader.py                 # HTTPX-загрузка HTML и извлечение текста Trafilatura.
    └── providers/
        └── searxng.py            # Только MCP SearXNG: поиск и разбор выдачи.
```

В `models.py` размещать только `AdditionalSource` и `AdditionalSearchResult`; не дублировать модели агента. **`providers/searxng.py` отвечает только за MCP-поиск** через Docker `mcp-searxng` (`searxng_web_search`) по Streamable HTTP и разбор поисковой выдачи. **`reader.py` отвечает за чтение статей** через общий `httpx.AsyncClient`, извлечение основного текста через Trafilatura и заполнение `AdditionalSource.text`. Инструменты, которыми существующий агент читает основную новость, включая `web_url_read`, **не вызывать в этом слое**. В `service.py` реализуется **одна публичная функция `search_additional_news(fact, query)`**: она проверяет вход, запускает поиск, выбирает публикации с разных сайтов, управляет лимитом пяти успешных текстов, вызывает `reader.py`, собирает `AdditionalSearchResult` с ошибками и возвращает его **после завершения чтения**. При промежуточном отборе кандидат может иметь `text=""`, но в возвращаемые `sources` включаются **только** публикации с заполненным непустым текстом. Прямые MCP/HTTP-операции и вызовы Trafilatura в `service.py` не размещать; отдельную `run_test()`, новую промежуточную модель, дополнительные публичные функции и архитектурные слои не создавать.

Пакет первоначально назывался `additional_sources` и проектировался внутри `agents/analysis_news`. Согласованное имя и расположение — **`data_sources/additional_news/`**. Путь этой спецификации — `specs/additional_news/spec-2026-11-07.md`.

## 3. Согласованные модели данных

```python
"""Модели дополнительных публикаций и результата поиска."""

from datetime import date
from typing import Literal, TypedDict


class AdditionalSource(TypedDict):
    """Содержит загруженную публикацию, найденную дополнительным поиском."""

    url: str  # Адрес найденной публикации.
    title: str | None  # Заголовок публикации, если доступен.
    text: str  # Весь доступный извлечённый основной текст статьи, не сниппет.
    published_date: date | Literal["unknown"]  # Дата публикации либо «unknown», если достоверно неизвестна.


class AdditionalSearchResult(TypedDict):
    """Содержит публикации, ошибки и предупреждение по результату поиска."""

    sources: list[AdditionalSource]  # Успешно загруженные публикации.
    errors: list[str]  # Ошибки поиска или загрузки отдельных публикаций.
    warning: str | None  # Предупреждение при отсутствии публикаций; None, если предупреждения нет.
```

**Принятые ограничения:**

- `AdditionalSearchResult` содержит **ровно три поля**: `sources`, `errors`, `warning`. Отдельное поле `status` не требуется; ошибки не добавлять в `AdditionalSource`. `warning` — текстовое предупреждение о том, что поиск завершился успешно, но публикаций нет; при других результатах `None`. Не добавлять это поле в `AgentState`.
- Публичная функция `service.py` возвращает **`AdditionalSearchResult`**, а не `list[AdditionalSource]` напрямую. Ранее обсуждавшийся отказ от контейнера отменён по решению пользователя.
- В `AdditionalSource.text` сохраняется **весь извлечённый основной текст статьи**, а не поисковый сниппет. Trafilatura не гарантирует извлечение абсолютно всех частей исходной веб-страницы. Публикацию без содержательного извлечённого текста нельзя выдавать как успешно загруженную.
- **Метаданные ранжирования (согласовано):** необязательные `score` и `engines` из расширенного результата SearXNG доступны **только внутри сервиса при отборе кандидатов**; в `AdditionalSource` и `AdditionalSearchResult` новые поля для них **не добавлять**. В первой версии сохраняется согласованный порядок SearXNG: собственную формулу оценки, сортировку по `score` или количеству `engines` не вводить до проверки реальной выдачи и отдельного решения. Наличие дополнительных поисковых систем не считать доказательством достоверности публикации.
- Значение `published_date` — `date | Literal["unknown"]`; если достоверную дату определить нельзя, использовать строку `"unknown"`, **не `None` и не текущую дату**. При JSON-сериализации известную дату передавать как строку `YYYY-MM-DD`, неизвестную — как `"unknown"`. Исходное время и временную зону преобразовывать явно.
- **Порядок получения даты (согласовано):** сначала использовать дату публикации из метаданных конкретного поискового результата SearXNG (например, `publishedDate`) при условии достоверной интерпретации; если дата отсутствует или недостоверна — попробовать извлечь дату из доступных метаданных самой загруженной страницы. Если дату достоверно установить невозможно, использовать `"unknown"`. Не подменять дату публикации датой индексации, получения или текущей датой и не привлекать LLM для её определения.

## 4. Вход и публичный сервис

Входное поисковое задание содержит два смысловых поля:

- **`fact: str`** — утверждение, которое необходимо подтвердить или опровергнуть, с указанием конкретного эмитента.
- **`query: str`** — готовый запрос для SearXNG, сформированный вызывающей LLM с учётом эмитента и проверяемого факта.

**Разграничение заполнения `text` (согласовано):** `service.py` ведёт промежуточный список найденных кандидатов с URL, заголовком и датой, передаёт выбранные публикации в `reader.py` и принимает результат чтения. `reader.py` заполняет `AdditionalSource.text` результатом Trafilatura; если текст не извлечён, включает диагностику в `errors`, а не создаёт успешный источник. **`reader.py` возвращает `AdditionalSearchResult`**, в котором `sources` содержат только успешно прочитанные публикации, `errors` — ошибки *чтения*, `warning=None` (отсутствие публикаций оценивает только оркестратор). **`service.py` объединяет ошибки поиска с ошибками чтения, определяет итоговый `warning` и возвращает окончательный `AdditionalSearchResult` после завершения чтения.** Обязательное поле `text` в возвращаемом `AdditionalSource` непустое. Не возвращать клиенту промежуточные публикации с незаполненным `text` и не добавлять новую модель для кандидатов.

**Внутренний интерфейс `service.py` → `reader.py` (согласовано):**

```python
async def read_sources(sources: list[AdditionalSource], max_successful: int) -> AdditionalSearchResult:
    """Читает публикации и возвращает результат загрузки.

    :param sources: Кандидаты с URL, заголовком и датой; text пока пустой.
    :param max_successful: Максимальное число публикаций с успешно извлечённым текстом.
    :return: Результат с заполненными sources, ошибками чтения и warning=None.
    """
    ...
```

В `service.py` достаточно одной операции `read_result = await read_sources(candidates, max_successful=5)`, затем собрать окончательный результат из `read_result.sources`, ошибок обоих этапов и предупреждения при действительно пустой успешной выдаче. `reader.py` не обращается к SearXNG, не оценивает поисковую выдачу и не определяет итоговый `warning`. **Не создавать дополнительную модель результата и не возвращать кортеж `(sources, errors)`.**

**Публичный интерфейс согласован (уточнение):** асинхронная функция `search_additional_news(fact: str, query: str) -> AdditionalSearchResult` в `service.py`. Оба параметра обязательны. **LLM-эксперт вызывающей стороны формирует готовый `query`; слой передаёт его в `searxng_web_search` без самостоятельного составления нового запроса и без дополнительной LLM.** `fact` содержит проверяемое утверждение для вызывающей стороны и дальнейшей интерпретации результата, но **не используется для самостоятельного LLM-ранжирования или изменения готового `query`**. Текущий отбор определяется порядком SearXNG и уникальностью сайта. Функция вызывается как агентом, так и вручную; слой не импортирует `VerifyTask` из агента и не зависит от LangGraph.

```python
async def search_additional_news(fact: str, query: str) -> AdditionalSearchResult:
    """Ищет дополнительные публикации для проверки факта.

    :param fact: Проверяемое утверждение о конкретном эмитенте.
    :param query: Готовый поисковый запрос, сформированный вызывающей LLM.
    :return: Полученные публикации и сообщения об ошибках.
    """
    ...  # Реализация определяется после согласования поиска и загрузки текстов.
```

**Простая проверка входа (согласовано):** если `fact` или `query` пустые либо состоят только из пробелов, **не обращаться к SearXNG** и сразу возвращать `{"sources": [], "errors": ["Не указан проверяемый факт или поисковый запрос."], "warning": None}`. Достаточно одного условия `if not fact.strip() or not query.strip(): ...` в существующей публичной функции. Не создавать отдельный валидатор, дополнительные исключения, классы или уровни абстракции только ради этой проверки. Если оба значения заполнены, передавать готовый `query` без переформулирования.

**Решение о формировании запроса:** `query` генерируется заранее LLM-экспертом потребителя и должен содержать достаточный контекст эмитента и финансовой темы. `additional_news` выполняет этот запрос, выбирает первые результаты с разных сайтов в порядке SearXNG и получает основной текст публикаций; собственной оценки релевантности по `fact` и отдельного вызова LLM здесь нет.

**Ручной запуск той же публичной функции** (без отдельной `run_test()`):

```python
if __name__ == "__main__":
    import asyncio

    asyncio.run(search_additional_news(
        fact="АО «ГТЛК» увеличило чистый долг по итогам последнего отчётного периода.",
        query="ГТЛК чистый долг динамика последняя отчётность МСФО",
    ))
```

Утверждение о ГТЛК — **предмет проверки**, а не установленный финансовый факт. Поисковую строку в ручном сценарии задаёт разработчик; при вызове из графа её формирует LLM-эксперт. Ручной запуск реализуется **прямым вызовом единственной публичной функции** с параметрами, как в других сервисах проекта; `if __name__ == "__main__"` содержит только пример вызова, а не дополнительный метод. Отдельный CLI, `argparse`, параметры командной строки и отдельный CLI-`main()` **не нужны**. Ручная функция и вызывающий агент используют одну общую реализацию поиска; генерация поисковой строки остаётся ответственностью вызывающей стороны.

## 5. Провайдер и получение публикаций

**Выбранный MCP-провайдер:** [ihor-sokoliuk/mcp-searxng](https://github.com/ihor-sokoliuk/mcp-searxng), транспорт **Streamable HTTP**. **Адрес Docker MCP задаётся константой `SEARXNG_MCP_URL` в `data_sources/additional_news/config.py`**, откуда его импортирует `providers/searxng.py`; не передавать адрес через переменную окружения `SEARXNG_MCP_URL` и не дублировать адрес внутри провайдера или сервиса. Конкретное значение адреса пока не указано и должно соответствовать фактическому развёртыванию. **Единый таймаут `MCP_TIMEOUT = 30` секунд хранится в `config.py` и используется как для клиентского MCP-вызова, так и для HTTPX-загрузки статей (`timeout=MCP_TIMEOUT`).** Отдельную константу HTTP-таймаута не вводить. Таймаут HTTPX применяется к сетевым операциям, а не гарантирует ограничение общего времени всех загрузок одним 30-секундным интервалом.

**Аутентификация (согласовано):** Docker MCP ещё не развёрнут; **для планируемого развертывания обязательно использовать статический Bearer-токен**. У самого SearXNG нет обязательного коммерческого API-ключа, а Docker MCP `mcp-searxng` поддерживает защищённый HTTP-режим (`MCP_HTTP_HARDEN=true`, серверный секрет `MCP_HTTP_AUTH_TOKEN`; дополнительные необходимые настройки защиты задаются при развёртывании). В Python-клиенте токен **обязательно читать из переменной окружения `SEARXNG_MCP_TOKEN`**, не хранить в `config.py`, исходниках, URL, спецификации или журнале. Провайдер передаёт `Authorization: Bearer <token>` с каждым MCP-запросом. **Если токен не задан или пустой, не начинать MCP-соединение**: вернуть диагностическое сообщение в `AdditionalSearchResult.errors` и `sources=[]` без раскрытия секрета. При отказе авторизации (например, HTTP 401/403) возвращать диагностическую ошибку, не переходить в незащищённый режим. OAuth не использовать в текущей реализации.

**Отдельная граница:** если сам SearXNG за MCP дополнительно защищён HTTP Basic Auth, это другая аутентификация между Docker MCP и поисковым сервером. Её настройки задаются в окружении Docker MCP (например, `AUTH_USERNAME`/`AUTH_PASSWORD` либо учётные данные в серверном `SEARXNG_URL`), а не в `data_sources/additional_news/config.py`. Не путать `SEARXNG_URL` Docker-процесса с константой адреса **MCP endpoint** `SEARXNG_MCP_URL` в Python-клиенте.

Документация: [Configuration Reference — Authentication и HTTP transport](https://github.com/ihor-sokoliuk/mcp-searxng/blob/main/CONFIGURATION.md), [HTTP server — authentication choices](https://github.com/ihor-sokoliuk/mcp-searxng/blob/main/docs/http-server.md).

Проверенные возможности `searxng_web_search`:

- Принимает `query` (без дополнительной LLM-генерации внутри сервиса), `num_results`, а также параметры `response_format="json"` и `result_detail="full"`. Последняя комбинация — изученная возможность, но конкретные параметры вызова ещё не утверждены как публичный контракт.
- JSON-выдача может включать `results[]` с `title`, `url`, `content`, а также необязательные дату `publishedDate`, `score`, `engines`, `category` и другую поисковую метаинформацию.
- `content` внутри поискового результата — **сниппет**, а не полный текст статьи. Режим `result_detail="full"` не означает скачивание полного содержимого сайта.
- JSON содержится в текстовом MCP-блоке `content[].text`, поэтому провайдеру необходим разбор ответа. Для JSON-поиска нужен корректно настроенный экземпляр SearXNG; MCP-сервер и сам SearXNG — разные компоненты.

**Согласованный цикл (получение текста определено):** нода LangGraph `additional_search()` напрямую вызывает `search_additional_news(fact, query)` → `service.py` передаёт готовый `query` в `providers/searxng.py` → провайдер выполняет `searxng_web_search` через Docker `mcp-searxng` и возвращает результаты → сервис отбирает URL разных сайтов → `reader.py` загружает HTML через `httpx.AsyncClient`, извлекает текст с помощью Trafilatura и заполняет `AdditionalSource.text` → `service.py` собирает `AdditionalSearchResult` только с успешно прочитанными публикациями и возвращает результат. Поисковое поле `content` — сниппет, **не** статья. Для HTML-извлечения использовать Markdown (`output_format="markdown"`) с сохранением таблиц (`include_tables=True`); не добавлять браузерный движок, Playwright, собственный HTML-парсер или новый слой без необходимости. Если страница недоступна, формат не поддерживается либо извлечение не дало содержательного текста, источник не включать в `sources`: указать URL и причину в `errors`, перейти к следующему допустимому сайту. Trafilatura выделяет основной текст, но **не гарантирует абсолютную полноту страницы**, особенно для JavaScript-подгружаемых и закрытых материалов.

**HTTP-перенаправления (согласовано):** разрешить **не более трёх переходов** для каждого исходного URL статьи. Для HTTP-загрузки использовать `httpx.AsyncClient` с `follow_redirects=False`; каждый ответ с `Location` обрабатывать последовательно, перед **каждым** новым запросом проверяя целевой адрес. Разрешены только публичные `http`/`https` URL; запрещены локальные, внутренние и служебные IP-адреса, включая адреса, полученные после DNS-разрешения и перенаправления. Если адрес недопустим, перенаправлений больше трёх или переход некорректен, **прекратить загрузку данного источника**, сохранить URL и причину отказа в `AdditionalSearchResult.errors`, продолжить со следующим допустимым сайтом. Автоматическое следование редиректам без проверки адресов не использовать. **Не вводить отдельные архитектурные слои и сложный механизм повторных запросов** ради этого правила. При реализации и тестировании проверить невозможность обращения к локальным/внутренним адресам, в том числе при изменении DNS-ответа между проверкой и подключением; если безопасный запрос гарантировать нельзя, URL отклонять.

**Тип HTTP-содержимого (согласовано):** перед передачей ответа в Trafilatura проверять заголовок `Content-Type` у успешного конечного HTTP-ответа, после разрешённых редиректов. Принимать только `text/html` и `application/xhtml+xml` (дополнительные параметры заголовка, например `charset`, не учитываются при сравнении). Если заголовок отсутствует или содержит другой MIME-тип — **не обрабатывать тело страницы**, добавить в `AdditionalSearchResult.errors` короткую диагностику с безопасным URL и полученным типом (или отметкой об отсутствии заголовка), затем перейти к следующему допустимому сайту. PDF, изображения, JSON, XML, документы и другие типы не поддерживать; не добавлять парсеры, конвертеры или резервные алгоритмы ради них. Проверка должна быть простым условием в `reader.py`; публичную функцию `search_additional_news()` не усложнять.

**Кодировка HTML (согласовано):** использовать штатное определение/декодирование кодировки в HTTPX при получении HTML, без собственных детекторов кодировки, перебора кодировок и дополнительных библиотек. Декодированный HTML передавать в `trafilatura.extract()`. Если возникла выявляемая ошибка декодирования или извлечение из полученного текста не удалось, не создавать публикацию, зафиксировать безопасный URL и причину в `AdditionalSearchResult.errors`, перейти к следующему сайту без повторной загрузки. **Не обещать обнаружение любой неверной кодировки:** HTTPX в отдельных случаях декодирует с заменой ошибочных символов, поэтому отсутствие исключения не доказывает корректность текста; отдельную эвристическую проверку на «битую» кодировку не вводить.

**Пустой результат извлечения (согласовано):** если `trafilatura.extract()` вернула `None`, пустую строку или только пробельные символы (`not text or not text.strip()`), считать загрузку публикации неуспешной: **не создавать `AdditionalSource`**, добавить в `AdditionalSearchResult.errors` короткое сообщение с безопасным URL и причиной «не удалось извлечь текст» и перейти к следующему допустимому сайту. Не заменять текст сниппетом SearXNG, не выполнять повторную загрузку и не добавлять другие алгоритмы извлечения. Отдельный минимальный порог длины статьи не вводить: непустой результат сохраняется целиком.

**Предельный размер загружаемого HTML (согласовано):** в `data_sources/additional_news/config.py` установить `MAX_HTML_SIZE_BYTES = 10 * 1024 * 1024` (**10 МиБ = 10 485 760 байт**). Ограничение относится к **телу загружаемого HTML**, а **не** к результату Trafilatura. Загружать страницу потоково через HTTPX (`response.aiter_bytes()`), суммировать полученные байты и прекращать чтение при превышении лимита; если `Content-Length` явно превышает лимит, можно отклонить ответ заранее, но отсутствие или некорректность заголовка не отменяет потоковую проверку. При превышении **полностью отклонить публикацию**, не выполнять Trafilatura на частичном HTML, добавить безопасный URL и причину в `AdditionalSearchResult.errors`, затем перейти к следующему допустимому источнику. Если весь HTML получен в пределах лимита, декодировать и передать его в Trafilatura без дополнительной обрезки. Не добавлять отдельные классы или новые параметры публичной функции ради ограничения.

**Объём извлечённого текста (согласовано):** слой `additional_news` **не устанавливает собственного ограничения длины** `AdditionalSource.text` и **не обрезает результат** `trafilatura`. Сохраняется весь извлечённый основной текст в Markdown с таблицами; последующая суммаризация выполняется в нодах LangGraph и не относится к слою данных. Если HTTP-ответ или механизм извлечения **явно сообщает об обрезке/частичном содержимом**, такой источник не считать успешным: указать URL и причину в `errors` и перейти к следующему сайту. Если таких признаков нет, не выдумывать их и не обещать абсолютную полноту. Не заменять отсутствующий текст поисковым сниппетом.

**Лимиты поиска и чтения (согласовано):** один готовый `query` передаётся в `searxng_web_search` с `num_results=10` (максимум 10 результатов поиска). Из выдачи последовательно выбираются **первые публикации с разных сайтов** в исходном порядке SearXNG. **Дубликат — любая следующая публикация с того же сайта, даже если URL и заголовок отличаются.** От каждого сайта допускается не более одной публикации: выбирается первый встретившийся URL этого сайта; остальные пропускаются. Сервис должен получить **не более 5 успешно загруженных публикаций с извлечённым основным текстом с разных сайтов** из не более чем 10 кандидатов; загрузку HTML и извлечение выполняет `reader.py` с помощью HTTPX и Trafilatura. Если чтение страницы не удалось, причина добавляется в `errors`, а сервис переходит к **следующему сайту**, не повторяя запрос для уже обработанного сайта. Успешные публикации сохраняются в `sources` в порядке выдачи. Таким образом, **максимум 5 успешных публикаций**, **до 10 попыток чтения** (если все 10 результатов относятся к разным сайтам). **Дополнительная оценка релевантности по `fact`, собственное ранжирование и LLM-отбор в текущую версию не входят**: первичный порядок полностью задаёт SearXNG. **Не усложнять обработку доменов и субдоменов на этапе проектирования**: сначала использовать возможности выдачи SearXNG и минимальную проверку повторения сайта в сервисе. Специальные правила объединения `www`, поддоменов и иных доменных вариантов сейчас не проектировать; к ним возвращаться только при обнаружении реальных дублей в тестах. Не предполагать без проверки, что SearXNG гарантированно исключает все публикации с одного сайта.

**Организация асинхронной загрузки (согласовано):** для выбранных URL использовать асинхронные задачи `asyncio` с общим `asyncio.Semaphore(DOWNLOAD_CONCURRENCY)` в `reader.py`. **Настройка семафора хранится в `data_sources/additional_news/config.py` как `DOWNLOAD_CONCURRENCY = 1`; модуль чтения импортирует эту константу.** Она задаёт максимальное число одновременных HTTP-загрузок; при текущем значении **фактической параллельной HTTP-загрузки нет**. Для изменения параллелизма в будущем достаточно изменить значение константы, без нового конфигурационного слоя. Не добавлять пул воркеров, очереди или отдельные классы ради семафора. Сохранить порядок кандидатов исходной выдачи SearXNG при формировании `sources` и `errors`, независимо от планирования задач. **Лимиты остаются прежними:** не более 10 кандидатов с разных сайтов, прекращать новые обращения к сайтам после получения 5 успешных публикаций; если задачи создаются заранее, проверять достижение лимита **внутри секции семафора до HTTP-запроса**, чтобы оставшиеся задачи не загружали лишние страницы. Ошибки одного URL не должны отменять результаты других. HTTP-загрузка и извлечение текста находятся в `reader.py`; MCP-поиск — в провайдере. Оркестрацию лимита успешных публикаций сохранять в `service.py`, не усложняя его сетевой логикой.

**Повторное использование HTTP-клиента (согласовано):** на **один вызов** `search_additional_news(fact, query)` создавать **один** `httpx.AsyncClient` для всех загрузок найденных HTML-страниц, включая разрешённые перенаправления. Создание, совместное использование задачами и закрытие клиента выполнять **в `reader.py`** через `async with httpx.AsyncClient(follow_redirects=False, timeout=MCP_TIMEOUT) as client`. Не создавать отдельный клиент на каждый URL и не хранить глобальный долгоживущий клиент между вызовами сервиса. `async with` обеспечивает закрытие при штатном завершении и ошибках; задачи должны завершаться/отменяться корректно до выхода из контекста. Значение `DOWNLOAD_CONCURRENCY` продолжает ограничивать число одновременных запросов; дополнительный пул клиентов, менеджер сессий или новый публичный метод не нужен. Сам `service.py` не должен управлять HTTPX-клиентом.

**Кэширование (согласовано):** собственный кэш результатов поиска и текстов публикаций в `data_sources/additional_news` **не использовать**. Каждый вызов `search_additional_news(fact, query)` запускает новый поиск через SearXNG и чтение выбранных страниц. Не добавлять TTL, хранилище, фоновые обновления или конфигурацию кэша. Это ограничение касается реализации слоя; поведение внутренних механизмов стороннего Docker MCP здесь не переопределяется.

**Пометка на будущее (не согласованная текущая функциональность):** предусмотреть возможность позднее добавить **LLM-отбор наиболее подходящих публикаций** из поисковой выдачи с учётом `fact`, не меняя публичный контракт `search_additional_news(fact, query)`. Для текущей реализации LLM-отбор **не выполнять** и не вводить преждевременно дополнительные классы, интерфейсы или конфигурационные переключатели.

**Разделение инструментов и нод:** существующий механизм чтения основной новости внутри `agents/analysis_news` **не используется** для дополнительных публикаций. Нода `additional_search()` непосредственно вызывает `search_additional_news(fact, query)`; `providers/searxng.py` ищет URL через MCP SearXNG, а `reader.py` загружает найденные HTML-страницы через HTTPX и извлекает текст с помощью Trafilatura. `additional_search` — имя ноды LangGraph, `search_additional_news` — публичная функция слоя, `searxng_web_search` — внутренний MCP-инструмент поиска. Дополнительные URL не направлять в `assistant` / общий `ToolNode` и не использовать `web_url_read`.

Сервис не вызывает LLM и не выполняет суммаризацию. Извлечение проверяемых фактов и проверка точности сокращений относятся к анализирующему агенту, а не к слою получения данных.

Ссылки на изученные исходники MCP: [types.ts](https://github.com/ihor-sokoliuk/mcp-searxng/blob/main/src/types.ts), [search.ts](https://github.com/ihor-sokoliuk/mcp-searxng/blob/main/src/search.ts), [описание инструментов](https://github.com/ihor-sokoliuk/mcp-searxng/blob/main/docs/tools.md).

**Внешний контракт поиска:** согласно документации [`mcp-searxng` — инструменты](https://github.com/ihor-sokoliuk/mcp-searxng/blob/main/docs/tools.md), `searxng_web_search` возвращает результаты поиска и сниппеты, но не полные статьи. Для содержимого найденных новостей утверждены **HTTPX + Trafilatura** в нашем провайдере, без использования инструмента чтения основной новости.

## 6. Результаты и обработка ошибок

Результаты различаются без отдельного поля `status`:

| `sources` | `errors` | `warning` | Значение |
|---|---|---|---|
| Не пуст | Пуст | `None` | Успешно получены публикации |
| Не пуст | Не пуст | `None` | Частичный результат с ошибками |
| Пуст | Пуст | `"Дополнительные публикации не найдены."` | Поиск завершён успешно, но публикаций нет |
| Пуст | Не пуст | `None` | Поиск/загрузка не дали публикаций и сопровождались ошибками; это **не** подтверждает отсутствие сведений |

**Пример успешной пустой выдачи:** `{"sources": [], "errors": [], "warning": "Дополнительные публикации не найдены."}`. Предупреждение находится **в результате сервиса**, не только в `logging`. `errors` используется для технических ошибок, `warning` — для отсутствия публикаций после успешного поиска. Не объявлять отсутствие публикаций ошибкой.

**HTTP-ошибки при загрузке публикаций (согласовано):** любой ответ `4xx` или `5xx` от сайта найденной новости считать **неудачной загрузкой**. Не передавать тело такого ответа в Trafilatura и не включать источник в `AdditionalSearchResult.sources`. Добавить в `AdditionalSearchResult.errors` короткую строку с **кодом HTTP и безопасным URL**, затем переходить к следующему допустимому сайту. **Повторных HTTP-запросов не выполнять**, в том числе для `429` и `5xx`. Для этого достаточно обычной проверки статуса ответа HTTPX; не создавать новые классы исключений, обработчики или уровни абстракции. Уже успешно загруженные публикации сохранять.

**Ограничение частоты (`429 Too Many Requests`, согласовано):** при получении ответа HTTP 429 от Docker MCP, SearXNG или сайта найденной публикации **не выполнять автоматический повтор того же запроса**. Сохранить диагностическое сообщение в `errors`, не добавлять фиктивные публикации. Если ошибка произошла на этапе поиска, вернуть результат с пустыми `sources`; если до неё уже загружены другие публикации, сохранить их в `sources`. Не реализовывать `retry`, `sleep`, экспоненциальную задержку, очередь или отдельный обработчик лимитов для этого случая. Поведение внутреннего Docker MCP вне контроля Python-клиента отдельно не переопределяется.

**Согласованный подход к ошибкам:** для ошибок `warning=None`; ошибки подключения к MCP, таймауты, некорректные ответы, ошибки HTTPX, неподдерживаемый тип содержимого и отсутствие текста после Trafilatura фиксировать строками в `AdditionalSearchResult.errors`, без отдельного поля `status` и без собственной иерархии исключений. Если поисковый запрос полностью завершился ошибкой, возвращать `sources=[]` с соответствующей диагностикой в `errors`; успешную пустую выдачу отличать от технического отказа. Если некоторые публикации получены успешно, возвращать их в `sources` вместе с накопленными ошибками. При невозможности получить полную публикацию не формировать фиктивный `AdditionalSource` и переходить к следующему допустимому сайту, пока не исчерпаны кандидаты или не получены пять успешных текстов. Ошибки провайдера обрабатывать **минимально необходимым способом**, без избыточных обёрток, дополнительных классов и дублирующих механизмов. Диагностика должна содержать контекст операции и URL при наличии, но не раскрывать секреты или токены. Конкретный формат строки ошибки остаётся деталью реализации.

**Журналирование (согласовано):** использовать стандартный Python `logging` и уровни действующей конфигурации приложения; не создавать отдельную систему логирования, отдельный файл журнала, дополнительный публичный метод или новые модели. Модули `service.py`, `reader.py` и `providers/searxng.py` используют собственные именованные логгеры через `logging.getLogger(__name__)`, не вызывают `logging.basicConfig()` и не меняют глобальный уровень логирования.

- `INFO`: начало/завершение поиска, количество результатов SearXNG, количество успешно полученных публикаций и общее время выполнения.
- `DEBUG`: расширенная пошаговая диагностика — MCP-поиск, HTTPX-загрузка и извлечение Trafilatura, число уникальных сайтов, отбор и пропуск кандидатов с причинами, переход к следующему сайту, результат загрузки каждого URL, размер извлечённого текста, источник даты (`SearXNG` / метаданные страницы / `unknown`), длительность операций и итоговые счётчики.
- `WARNING`/`ERROR`: сбои соединения, отказ авторизации, таймаут, HTTP `4xx`/`5xx` (включая `429`), некорректный MCP-ответ, недоступная либо обрезанная публикация; сохранять контекст операции и безопасный URL, не дублировать одну ошибку многократно.

**Защита данных в любом режиме:** не логировать Bearer-токены, переменные окружения с секретами, заголовки авторизации, полный текст статьи, сырой MCP-ответ или произвольные запросы и факты целиком. URL перед логированием очищать от учётных данных и чувствительных параметров; если безопасно очистить нельзя, записать только адрес сайта/идентификатор операции. Расширенный `DEBUG` включается стандартной настройкой уровня логирования приложения, без специального флага в `config.py`. Журналирование не должно подменять данные `AdditionalSearchResult` или ограничивать количество возвращаемых символов. В частности, `warning` о пустой выдаче возвращается независимо от настройки `logging`.

## 7. Открытые вопросы реализации слоя

1. Формирование `query` вынесено в вызывающую LLM. Пустой `fact` или `query` (в том числе только пробелы) приводит к немедленному `AdditionalSearchResult` с пустыми `sources` и диагностикой в `errors` без обращения к провайдеру (согласовано). Проверка — одно простое условие внутри публичной функции; заполненный `query` передаётся без переформулирования.
2. **Способ получения текста согласован:** загружать HTML выбранного URL через `httpx.AsyncClient`, извлекать основной текст с помощью `trafilatura` в Markdown (`output_format="markdown"`, `include_tables=True`) внутри `reader.py`. `web_url_read` не использовать. **HTTP-перенаправления согласованы:** не более трёх с проверкой допустимости каждого целевого адреса и его фактического сетевого назначения, иначе ошибка в `errors` и переход к следующему сайту. **Типы ответа согласованы:** только `text/html` и `application/xhtml+xml`; отсутствующий или иной `Content-Type` — ошибка с переходом к следующему сайту без передачи ответа в Trafilatura. **Собственное ограничение длины извлечённого текста не вводить.** Пустой или пробельный результат Trafilatura считать неудачной загрузкой, писать ошибку и продолжать со следующим сайтом. Для кодировок согласовано стандартное декодирование HTTPX без самостоятельного распознавания; при выявленной ошибке декодирования или неудачном извлечении текста источник пропускать с диагностикой в `errors`. **Размер HTML ограничен 10 МиБ** с потоковой проверкой, превышение — ошибка без обработки частичной страницы; при реализации остаётся уточнить фактически доступные признаки обрезки. Не добавлять Playwright и отдельную систему извлечения.
3. Согласовано брать первые публикации **с разных сайтов**, не более одной публикации на сайт, до пяти успешных текстов либо исчерпания десяти результатов. Сложную нормализацию субдоменов не разрабатывать заранее; возможные реальные дубли проверить при тестировании SearXNG. **Собственный кэш не использовать (согласовано)**. LLM-отбор — только возможное будущее расширение.
4. Адрес Docker MCP — константа `SEARXNG_MCP_URL` в `config.py`; **единый таймаут MCP и HTTPX — `MCP_TIMEOUT = 30` секунд**, без отдельной HTTP-константы; число одновременных HTTP-загрузок — константа `DOWNLOAD_CONCURRENCY = 1`, размер HTML — `MAX_HTML_SIZE_BYTES = 10 * 1024 * 1024` в `config.py` (согласовано). **Статическая Bearer-авторизация обязательна**, хотя Docker MCP пока не развёрнут: серверный секрет `MCP_HTTP_AUTH_TOKEN` передаётся контейнеру через окружение, клиент читает `SEARXNG_MCP_TOKEN` из своего окружения. Без клиентского токена соединение не выполнять, возвращать ошибку. При развёртывании ещё установить фактический URL MCP и параметры защищённого HTTP-режима; журналирование через стандартный `logging` с подробной диагностикой на уровне `DEBUG` (согласовано). Автоматические повторные запросы при `429` не выполнять (согласовано). Общий подход к ошибкам: диагностические строки в `errors`, сохранение успешных источников, без иерархии исключений.
5. Порядок извлечения даты согласован: сначала метаданные SearXNG, затем метаданные страницы; если надёжной даты нет — `"unknown"`. При реализации проверить допустимые форматы дат и корректную обработку недостоверных/неоднозначных значений.
6. Тесты сервиса: пустая выдача, частичная HTTPX-загрузка, успешное извлечение текста и таблиц Trafilatura из HTML, пустой результат извлечения, неподдерживаемый формат, повреждённый MCP-ответ, ошибки сети и отсутствие даты; отдельно проверить HTML ровно 10 МиБ, превышение на 1 байт, отсутствие/ложный `Content-Length` и отказ от извлечения частичной страницы. Проверить защиту от обращения к внутренним/локальным адресам и редиректов на них. Отдельно проверить `asyncio.Semaphore(DOWNLOAD_CONCURRENCY)` при `DOWNLOAD_CONCURRENCY = 1`: одновременно выполняется не более одной загрузки, порядок выдачи сохраняется, после пяти успешных публикаций лишние HTTP-запросы не выполняются, ошибка одного источника не прерывает обработку остальных. Проверить, что в пределах одного вызова сервиса создаётся один `httpx.AsyncClient` с `timeout=MCP_TIMEOUT`, он переиспользуется всеми загрузками и закрывается при успехе или ошибке; таймаут загрузки фиксируется в `errors`, не отменяя уже успешные источники.

## 8. Результат итоговой проверки спецификации (2026-11-09)

**Проверено:** границы `service.py` и провайдера, полнота доступного извлечённого текста, схемы `AdditionalSource`/`AdditionalSearchResult`, источники даты, ограничение 10 результатов → до 5 публикаций с разных сайтов, HTTPX/Trafilatura, авторизация, ошибки, семафор и общий HTTP-клиент. Публичный контракт **не меняется**. Логику маршрутизации и лимиты поисков LangGraph здесь не определять.

**Устранённая неточность:** ранее в разделах 3–4 говорилось об отборе «релевантных» публикаций по `fact`, хотя раздел 5 исключает дополнительное ранжирование; оставлен только согласованный отбор по порядку SearXNG и различным сайтам. Термин «полный текст» уточнён как весь доступный **извлечённый основной текст**, без обещания абсолютной полноты страницы.

**Технические вопросы, которые нужно проверить до заявления о готовности реализации:**

1. **Безопасность исходящих HTTP-запросов:** проверка строки URL или предварительное DNS-разрешение сами по себе не гарантируют защиты от DNS rebinding (адрес может измениться до фактического подключения HTTPX). Перед запуском обеспечить защиту *фактического сетевого подключения* и каждого редиректа от локальных/приватных адресов либо ограничить исходящий трафик на уровне окружения; небезопасные URL отклонять. Не считать этот пункт выполненным без теста. Минимальная реализация не должна жертвовать этой границей безопасности.
2. **Проверка живого MCP:** конкретный `SEARXNG_MCP_URL` и защищённый Docker MCP пока не настроены. На целевом экземпляре проверить `searxng_web_search` с JSON-ответом, формат `content[].text`, необязательные метаданные, ошибки и лимит десяти результатов. Не подменять испытания предположением по документации.
3. **Ресурсная нагрузка (решение согласовано):** загружаемый HTML ограничен 10 МиБ через `MAX_HTML_SIZE_BYTES` с потоковой проверкой; при превышении публикация отклоняется целиком, без извлечения из обрезанного HTML. Размер результата Trafilatura отдельно не ограничивается. Проверить граничные значения и ложный/отсутствующий `Content-Length`.
4. **Асинхронная обработка:** при `DOWNLOAD_CONCURRENCY = 1` одновременно загружается максимум одна страница. При создании нескольких задач проверить завершение или пропуск оставшихся после пяти успехов, сохранение исходного порядка и закрытие общего `httpx.AsyncClient` даже при ошибках. Нельзя считать наличие семафора доказательством корректности остановки.

**Критерий готовности:** спецификация определяет необходимое поведение, но политика обработки чрезмерно больших HTML-ответов теперь согласована; до утверждения реализации отдельно остаются технические проверки, описанные выше. Технические вопросы решать в соответствующих модулях, **не расширяя публичный сервис и модели**. Программный код не изменялся; тесты пока не запускались.
