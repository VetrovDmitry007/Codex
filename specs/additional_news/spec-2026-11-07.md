**Проект:** BondNavigator  
**Компонент:** `data_sources/additional_news`  
**Дата начала:** 2026-11-07  
**Статус:** черновик; записаны согласованные решения, открытые вопросы отмечены отдельно. Программный код не изменён.

**Спецификация потребителя:** [контракт узла LangGraph `additional_search`](../analysis_news/additional-search-node-2026-11-07.md). Граф, `AgentState`, `SourceData`, суммаризация, валидация и маршрутизация находятся **только в документе узла**, не в этой спецификации.

## 1. Назначение и границы

Создать независимый от LangGraph пакет получения **дополнительных публикаций** для проверки факта о конкретном эмитенте. Слой принимает проверяемое утверждение и вопрос, ищет источники через MCP SearXNG, выбирает подходящие публикации, самостоятельно получает их **полные тексты** и возвращает структурированные данные и диагностические сообщения.

В пакет **не входят** LLM-суммаризация, экспертная оценка достоверности факта, управление состоянием графа и маршрутизация агента. Эти функции реализует потребитель. Пакет должен быть пригоден для вызова из других частей проекта и для ручного тестирования без LangGraph.

## 2. Архитектура файлов

```text
data_sources/
└── additional_news/
    ├── models.py                 # Модели публикаций и результата поиска.
    ├── service.py                # Публичный сервис, оркестрация поиска и ручной запуск.
    └── providers/
        └── searxng.py            # MCP SearXNG через Streamable HTTP.
```

В `models.py` размещать только `AdditionalSource` и `AdditionalSearchResult`; не дублировать модели агента. Взаимодействие с внешним MCP отделить от формирования результата сервиса. Не создавать дополнительные архитектурные слои, повторные обходы отказов или самостоятельные механизмы суммаризации без обоснования.

Пакет первоначально назывался `additional_sources` и проектировался внутри `agents/analysis_news`. Согласованное имя и расположение — **`data_sources/additional_news/`**. Путь этой спецификации — `specs/additional_news/spec-2026-11-07.md`.

## 3. Согласованные модели данных

```python
"""Модели дополнительных публикаций и результата поиска."""

from datetime import date
from typing import TypedDict


class AdditionalSource(TypedDict):
    """Содержит загруженную публикацию, найденную дополнительным поиском."""

    url: str  # Адрес найденной публикации.
    title: str | None  # Заголовок публикации, если доступен.
    text: str  # Полученный полный текст публикации.
    published_date: date | None  # Дата публикации; None, если достоверно неизвестна.


class AdditionalSearchResult(TypedDict):
    """Объединяет полученные публикации и сообщения об ошибках."""

    sources: list[AdditionalSource]  # Успешно загруженные публикации.
    errors: list[str]  # Ошибки поиска или загрузки отдельных публикаций.
```

**Принятые ограничения:**

- `AdditionalSearchResult` содержит **ровно два поля** `sources` и `errors`. Отдельное поле `status` не требуется; ошибки не добавлять в `AdditionalSource`.
- Публичная функция `service.py` возвращает **`AdditionalSearchResult`**, а не `list[AdditionalSource]` напрямую. Ранее обсуждавшийся отказ от контейнера отменён по решению пользователя.
- В `AdditionalSource.text` сохраняется именно полученный **полный текст**, а не поисковый сниппет. Публикацию без доступного полного текста нельзя выдавать как успешно загруженную.
- Значение `published_date` — `date | None`; при отсутствии достоверной даты использовать `None`, не подменять текущей датой. Исходное время и временную зону преобразовывать явно.

## 4. Вход и публичный сервис

Входное поисковое задание содержит два смысловых поля:

- **`fact: str`** — утверждение, которое необходимо подтвердить или опровергнуть, с указанием конкретного эмитента.
- **`question: str`** — конкретный вопрос для дополнительного поиска в отношении этого факта и эмитента.

Ручной запуск с **обоими обязательными параметрами** согласован. Публичный сервис используется и агентом, и ручным вызовом; конкретное имя публичной функции и окончательная сигнатура ещё не утверждены. Слой не импортирует `VerifyTask` из агента: его собственный вход должен быть пригоден для независимого использования.

**Иллюстрация согласованной формы ручного запуска** (`search_additional_news` — условное имя публичной функции):

```python
async def run_test(fact: str, question: str) -> AdditionalSearchResult:
    """Вручную ищет публикации по факту и вопросу об эмитенте.

    :param fact: Проверяемое утверждение с названием эмитента.
    :param question: Вопрос для дополнительного поиска.
    :return: Найденные публикации и сообщения об ошибках.
    """
    return await search_additional_news(fact=fact, question=question)


if __name__ == "__main__":
    import asyncio

    asyncio.run(run_test(
        fact="АО «ГТЛК» увеличило чистый долг по итогам последнего отчётного периода.",
        question="Подтверждается ли увеличение чистого долга АО «ГТЛК» по последней доступной отчётности?",
    ))
```

Утверждение о ГТЛК — **предмет проверки**, а не установленный финансовый факт. Ручной запуск реализуется прямым вызовом функции с параметрами, как в других сервисах проекта. Отдельный CLI, `argparse`, параметры `--question` / `--fact` и отдельный CLI-`main()` **не нужны**. Ручная функция и вызывающий агент используют одну общую реализацию поиска.

## 5. Провайдер и получение публикаций

**Выбранный MCP-провайдер:** [ihor-sokoliuk/mcp-searxng](https://github.com/ihor-sokoliuk/mcp-searxng), транспорт **Streamable HTTP**. Конкретные адрес MCP-сервера, конфигурация и протокол обработки ошибок будут определены при детализации.

Проверенные возможности `searxng_web_search`:

- Принимает `query`, `num_results`, а также параметры `response_format="json"` и `result_detail="full"`. Последняя комбинация — изученная возможность, но конкретные параметры вызова ещё не утверждены как публичный контракт.
- JSON-выдача может включать `results[]` с `title`, `url`, `content`, а также необязательные дату `publishedDate`, `score`, `engines`, `category` и другую поисковую метаинформацию.
- `content` внутри поискового результата — **сниппет**, а не полный текст статьи. Режим `result_detail="full"` не означает скачивание полного содержимого сайта.
- JSON содержится в текстовом MCP-блоке `content[].text`, поэтому провайдеру необходим разбор ответа. Для JSON-поиска нужен корректно настроенный экземпляр SearXNG; MCP-сервер и сам SearXNG — разные компоненты.

**Согласованный цикл сервиса:** найти публикации через `searxng_web_search` → выбрать источники → **самостоятельно загрузить полные тексты** выбранных страниц → сформировать `AdditionalSearchResult`. Механизм HTTP-загрузки и ограничения ещё не согласованы. Для дополнительных ссылок **не использовать** внешний `Web URL Reader` / `web_url_read` и не делегировать загрузку LangGraph-агенту. `Web URL Reader` в существующей системе предназначен только для основной новости.

Сервис не вызывает LLM и не выполняет суммаризацию. Извлечение проверяемых фактов и проверка точности сокращений относятся к анализирующему агенту, а не к слою получения данных.

Ссылки на изученные исходники MCP: [types.ts](https://github.com/ihor-sokoliuk/mcp-searxng/blob/main/src/types.ts), [search.ts](https://github.com/ihor-sokoliuk/mcp-searxng/blob/main/src/search.ts), [описание инструментов](https://github.com/ihor-sokoliuk/mcp-searxng/blob/main/docs/tools.md).

## 6. Результаты и обработка ошибок

Результаты различаются без отдельного поля `status`:

| `sources` | `errors` | Значение |
|---|---|---|
| Не пуст | Пуст | Успешно получены публикации |
| Не пуст | Не пуст | Частичный результат с ошибками |
| Пуст | Пуст | Поиск завершён без найденных публикаций |
| Пуст | Не пуст | Поиск/загрузка не дали публикаций и сопровождались ошибками; это **не** подтверждает отсутствие сведений |

При невозможности загрузить отдельную публикацию не формировать фиктивный `AdditionalSource`. Ошибки внешнего MCP, таймауты, повреждённые ответы и ошибки получения страниц должны быть отличимы от пустой успешной выдачи; конкретный способ превращения исключений в сообщения `errors` ещё требуется согласовать. Диагностика не должна содержать секретов или токенов.

## 7. Открытые вопросы реализации слоя

1. Точное имя публичной функции `service.py`, её асинхронная сигнатура и способ передачи пары `fact` / `question` из внешних потребителей.
2. Чем получать и извлекать полные тексты URL внутри слоя данных, чтобы не использовать Web URL Reader; обработка HTML и недоступных страниц.
3. Критерии отбора источников, лимиты результатов, дедупликация URL и возможное кэширование.
4. Адреса и конфигурация MCP/SearXNG, таймауты, `429`, формат ошибок и записи в журнал.
5. Нормализация дат из поисковой выдачи и страниц, сохранение `None`, если дату нельзя определить достоверно.
6. Тесты сервиса: пустая выдача, частичная загрузка, повреждённый ответ, ошибки сети и отсутствие даты.
