# Задание Codex: MCP-клиент для загрузки JSON Skills

> **Для Codex:** реализуй задачу в исходном проекте BondNavigator. При планировании и разработке используй Superpowers (`writing-plans` и далее подходящий навык реализации), придерживайся существующей архитектуры и не расширяй объём задачи.

**Цель:** создать минимальный работоспособный клиентский слой получения JSON Skills с MCP-сервера: публичные асинхронные функции `get_skills()` и `get_skill(url_skill)` через **MCP Resources** и транспорт **Streamable HTTP**.

**Статус сервера:** по сообщению пользователя, оба MCP Resources уже реализованы. По актуальному `PROJECT_STRUCTURE(20261104-120209).md` в сервере есть `mcp_server/resources/skills.py` с `get_skills()`, `get_skill()` и `register_resources()`; в клиенте указан `mcp_client/config.py`. Это описание структуры, **не подтверждение успешных сетевых запросов**.

## Публичные функции клиента

Реализуй в подходящем модуле пакета `mcp_client/` две публичные функции с согласованными интерфейсами:

```python
from typing import Any


async def get_skills() -> list[dict[str, Any]]:
    """Загружает каталог основных Skills из MCP Resource сервера.

    :return: Список объектов с полями name, url_skill и description.
    :raises ConnectionError: Не удалось установить соединение с MCP-сервером.
    :raises ValueError: Ответ каталога не является корректной JSON-структурой.
    """


async def get_skill(url_skill: str) -> dict[str, Any]:
    """Загружает полный JSON одного Skill по его MCP URI.

    :param url_skill: Полный URI, например bondnavigator://get_skill/sub_portfolio_analysis.
    :return: JSON-объект основного или дочернего Skill без потери полей.
    :raises ValueError: URI или содержимое ответа некорректны.
    :raises ConnectionError: Не удалось установить соединение с MCP-сервером.
    """
```

Сигнатуры задают **внешний API клиентского слоя**; адаптируй типы ожидаемых исключений под существующий проект, документируя фактическую семантику. Организацию MCP-сессии, возможность переиспользования соединения и асинхронный жизненный цикл вынеси в небольшой общий слой **только если это необходимо**; не дублируй подключение и декодирование JSON в обеих функциях. Существующий `mcp_client/config.py` следует переиспользовать и дополнить минимально, если требуется.

### `get_skills()`

- Читай точный URI `bondnavigator://skills` операцией `resources/read` (например, SDK `ClientSession.read_resource`).
- Нормализуй MCP-ответ в `list[dict[str, Any]]`; проверь базовую структуру элементов `name: str`, `url_skill: str`, `description: str`.
- Возвращай **только то, что предоставил сервер**, без клиентского сканирования файлов и формирования реестра Skills.
- Допускай пустой корректный каталог; не подменяй ошибку сервера пустым списком.

### `get_skill(url_skill)`

- Принимай **полный URI** `bondnavigator://get_skill/{url_name}`, а не basename и не путь к JSON на диске.
- Проверяй ожидаемый URI и непустое безопасное `url_name`; не позволяй произвольно запрашивать посторонние MCP Resources через эту функцию.
- Читай указанный MCP Resource посредством `resources/read` и возвращай **полный JSON-объект**, сохраняя содержимое `subtasks` или `mcp_objects` без преобразования экономических/предметных данных.
- Обрабатывай ошибку «Skill не найден», отсутствие содержимого, некорректный JSON и неверный верхнеуровневый тип с понятной диагностикой.
- Не вводи тяжёлую схему Pydantic/JSON Schema; достаточно проверки типа корневой структуры и обязательных полей текущего основного/дочернего Skill, если она нужна для безопасного контракта.

### Подключение

- Используй **Streamable HTTP** и фактический API установленного MCP SDK. Не замещай протокол самодельным HTTP GET к URI `bondnavigator://...`.
- Конфигурация подключения — через существующий `mcp_client/config.py`; секреты и токены только из окружения, без хранения в коде, логах и исключениях.
- Сохрани согласованные внешние ограничения: таймаут обращения к MCP — **30 секунд**, не более **одной повторной попытки** для разрешённых временных ошибок (например, HTTP 429/502/503/504); ошибки авторизации, входных данных и JSON не повторять.
- Не создавай отдельные MCP Tools `get_skills`/`get_skill`. Это функции клиента, которые вызывают **серверные Resources**.

## Проверки и критерии готовности

1. `get_skills()` возвращает список основных Skills и корректно обрабатывает пустой каталог.
2. `get_skill("bondnavigator://get_skill/portfolio_cashflow")` возвращает JSON с `name`, `description`, `subtasks`.
3. Чтение `bondnavigator://get_skill/sub_portfolio_analysis` и `bondnavigator://get_skill/sub_month_cash_flow` возвращает исходные `description` и `mcp_objects` (не теряет 18 и 7 элементов соответственно, если на сервер загружены согласованные образцы).
4. Неизвестный Skill, недопустимый URI, невалидный JSON, пустой ответ и неверный тип результата дают объяснимую ошибку, а не фиктивный успешный ответ.
5. Ошибки сети/таймаута и авторизации корректно различаются; предусмотренные повторы соблюдают установленные ограничения; секреты в диагностике отсутствуют.
6. По возможности выполнен интеграционный тест против работающего MCP-сервера по Streamable HTTP, а также тесты с изолированным тестовым MCP-ответом без внешней сети.

**Результат:** две доступные из `mcp_client` публичные асинхронные функции, проверенные тестами. Выбирай расположение модулей по фактической структуре проекта; избегай лишних классов и слоёв. Для каждого модуля и функции — содержательный русский docstring, аннотации типов, PEP 8.

**Не входит в задачу:** изменения `mcp_server/` (если обнаружен серверный дефект — сообщи отдельно), LangGraph, ReAct, Task Selection, анализ портфеля, запуск основного Skill, MCP Prompt `assess_portfolio_quality`, CLIProxyAPI/LLM и реализация новостного слоя.

**Отчёт Codex:** точные пути изменённых файлов, фактические сигнатуры и контракт функций, использованный MCP SDK/транспорт, команда запуска `pytest`, число пройденных тестов, факт или отсутствие реальной интеграционной проверки, известные ограничения. Не утверждай о работающем подключении при проверке только на моках.
