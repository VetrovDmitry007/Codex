# Задание для Codex: два MCP Resources для JSON Skills

**Статус:** задание на реализацию в исходном проекте BondNavigator, не отчёт о выполненной работе.

**Цель:** реализовать или адаптировать на MCP-сервере два ресурса — `bondnavigator://skills` и `bondnavigator://get_skill/{url_name}` — и **соответствующие публичные Python-функции** для чтения JSON Skills. На этом этапе **не создавать MCP-клиент** и не реализовывать MCP Prompt `assess_portfolio_quality`.

## Источники требований

- [Основная спецификация](mcp-client-bondnavigator-2026-10-30.md), особенно §9.1–9.6 и §9.21.
- [Архитектура MCP-клиента](mcp-client-architecture-2026-10-29.md).
- Проектные образцы: [основной Skill](skills/portfolio_cashflow.json), [анализ портфеля](skills/sub_portfolio_analysis.json), [денежные потоки](skills/sub_month_cash_flow.json).

**Перед изменением кода:** изучи фактические модули MCP-сервера, существующие объявления Resources, публичные функции, места их вызова, структуру пакета, используемый MCP SDK и имеющиеся тесты. Если `bondnavigator://skills` уже существует, **адаптируй его**, не регистрируй дубликат. Не удаляй работающие старые Markdown Skills и не ломай их потребителей. Если обнаружено противоречие спецификации с фактическими публичными контрактами — сообщи о нём до несовместимого изменения.

## Публичные Python-функции

Реализуй две публичные функции на серверной стороне, доступные из соответствующего модуля (или переиспользуй совместимые существующие):

```python
from typing import Any


def get_skills() -> list[dict[str, Any]]:
    """Возвращает актуальный каталог основных JSON Skills.

    :return: Список основных Skills с name, url_skill, description.
    """


def get_skill(url_name: str) -> dict[str, Any]:
    """Читает и возвращает один основной или дочерний JSON Skill.

    :param url_name: Имя JSON-файла без расширения, например sub_portfolio_analysis.
    :return: Содержимое JSON Skill без потери исходных полей.
    :raises ValueError: Недопустимое имя Skill или некорректные данные.
    :raises FileNotFoundError: Skill с указанным именем отсутствует.
    """
```

Сигнатуры описывают **публичный контракт для серверной логики**. Если существующий код проекта требует асинхронных функций или других согласованных типов исключений, используй его стиль без изменения смысла контракта; задокументируй фактические сигнатуры. Внутренние функции чтения и минимальной проверки JSON вынеси из обработчиков MCP Resources, чтобы избежать дублирования.

**Важно:** это публичные функции **сервера**. Одноимённые функции будущего MCP-клиента `get_skills()` и `get_skill(url_skill)` должны обращаться к этим Resources через MCP `resources/read`, но **не входят в это задание**. Не регистрируй серверные функции как MCP Tools.

## MCP Resources

### 1. `bondnavigator://skills`

- Зарегистрируй или адаптируй **MCP Resource** с точным URI `bondnavigator://skills`.
- При **каждом запросе** просматривай каталог `mcp_server/skills/` с JSON-файлами **без кэша и без рестарта сервера**.
- Возвращай **только основные Skills**: JSON-файлы, чьё имя **не** начинается с `sub_`.
- Формат элемента каталога:

```json
{
  "name": "portfolio_cashflow",
  "url_skill": "bondnavigator://get_skill/portfolio_cashflow",
  "description": "Анализ облигационного портфеля с учётом выплат до конца месяца"
}
```

- Исключай некорректный файл из каталога с диагностикой, не прерывая чтение остальных основных Skills.
- Если недоступен сам каталог — возвращай диагностируемую ошибку, а не достоверно пустой список.
- Не открывай и не валидируй дочерние файлы `sub_*.json` при построении каталога.

### 2. `bondnavigator://get_skill/{url_name}`

- Зарегистрируй **MCP Resource template** с URI `bondnavigator://get_skill/{url_name}`.
- `url_name` — точный basename JSON-файла **без расширения**: `portfolio_cashflow`, `sub_portfolio_analysis`, `sub_month_cash_flow`.
- Читай соответствующий файл по запросу и возвращай **его полный JSON-объект**. Не переименовывай поля и не изменяй вложенные данные.
- Для неизвестного или недопустимого имени возвращай понятную ошибку. Не допускай `../`, символы путей, обход каталога и доступ к посторонним файлам.
- Применяй **минимальную** проверку: основной Skill — наличие `name: str`, `description: str`, `subtasks: list`; дочерний — `description: str`, `mcp_objects: list`. Тип определяется по префиксу имени файла `sub_`. Не вводи полный JSON Schema/Pydantic-валидатор без необходимости.
- Не подменяй ошибочный дочерний Skill другим файлом и не скрывай ошибку некорректного JSON.

Согласуй фактический способ возврата JSON с установленным MCP SDK: клиент должен получать корректно декодируемый JSON, а не Python-`repr` или Markdown-обёртку. Существующие контракты SDK сохраняй.

## Организация кода

- Раздели загрузку JSON, минимальную валидацию и регистрацию MCP Resources; используй уже существующую структуру проекта, не создавая избыточные слои.
- Не вводи ручной реестр имён JSON Skills и не правь регистрацию при добавлении нового JSON-файла.
- Если у действующего `bondnavigator://skills` есть потребители старого формата, сначала выяви их и обеспечь обратную совместимость либо явно укажи блокирующее расхождение.
- Все создаваемые/изменяемые модули, классы и функции снабди содержательными docstring **на русском**, соблюдай PEP 8 и аннотации типов.
- Разделяй диагностические ошибки чтения файлов, JSON-данных и ошибок MCP-вызова; не раскрывай секреты в сообщениях.

## Проверка: обязательный `pytest`

1. Каталог возвращает `portfolio_cashflow`, но не перечисляет `sub_portfolio_analysis` и `sub_month_cash_flow` среди основных.
2. `get_skill()` возвращает без потери данных каждый из трёх образцов JSON.
3. После добавления, изменения и удаления основного JSON Skill следующий запрос каталога отражает изменения без рестарта.
4. Некорректный основной JSON не блокирует остальные элементы каталога; прямой запрос некорректного Skill даёт ошибку.
5. Неизвестное имя, опасный путь, неверные обязательные поля, несоответствие `sub_` и структуры дают диагностируемые ошибки.
6. Отказ доступа ко всему каталогу не выдаётся за пустой каталог.
7. Интеграционная проверка MCP discovery: `resources/list` показывает `bondnavigator://skills`, `resources/templates/list` — `bondnavigator://get_skill/{url_name}`; вызовы `resources/read` возвращают корректный каталог и конкретный Skill.
8. Прогон существующих затронутых тестов и проверка сохранения прежних серверных Resources.

Создай временные тесты для основного сценария, граничных случаев и ошибок; выполни `pytest`, исправь выявленные дефекты и повтори тесты. В итоговом отчёте приведи **команду**, **количество успешных тестов**, фактически проверенные сценарии и ограничения. Не утверждай, что тестирование выполнено, если запуск не состоялся.

## Критерии готовности

- На MCP-сервере доступны **оба** требуемых Resources, а серверная логика реализована через **две соответствующие публичные функции**.
- Каталог и выдача JSON совместимы с тремя проектными файлами и решениями §9.1–9.6.
- Существующие интерфейсы не сломаны, тесты пройдены.
- **Не входят в задачу:** клиентские функции, каркас `mcp_client/`, LangGraph, новостной скоринг, `assess_portfolio_quality` и другие MCP Prompts.

**Формат результата Codex:** кратко перечисли реальные изменённые файлы и публичные функции, способ регистрации Resources, итог `pytest` и известные ограничения.
