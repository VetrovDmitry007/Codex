# Результаты поиска станций — рамки архитектуры

**Статус:** ЧЕРНОВИК; **не утверждён к реализации** (2026-11-13).  
**Утверждён только графический макет:** [station-search-results-approved.jpg](./station-search-results-approved.jpg) и [UX-требования](./requirements.md).

## Разделение ответственности — согласованный принцип (2026-11-13)

**Widget — только представление готовых результатов поиска.** Он получает от вызывающего обработчика список станций с исходными названиями и кодами и **отображает** их по утверждённому макету (по `page_size` на странице, **по умолчанию 5** по утверждённому макету, локальные визуальные действия навигации). Нажатие на карточку лишь сообщает наружу идентификатор выбранного элемента; Widget **не ищет станции, не обращается к РЖД, не выполняет бизнес-валидацию, не принимает решений о сохранении, не изменяет FSM и не выбирает станцию автоматически**.

**Существующие обработчики и бизнес-логика TrainBot** формируют список по пользовательскому запросу, определяют, когда и какие результаты передавать виджету, обрабатывают событие выбора, проверяют код и контекст, сохраняют станцию и управляют сообщениями/возвратом в меню. **Условие запуска согласовано (2026-11-13):** существующий обработчик вызывает Widget **только после формирования непустого списка станций** (минимум один результат). Если список отсутствует или пустой, Widget **не создаётся и не отправляется**; сценарий нулевого результата остаётся за существующим кодом TrainBot. Поведение самого TrainBot при нулевом результате этой спецификацией не изменяется.

Это согласование **границы ответственности**, а не утверждение протокола передачи данных или реализации. Детали доставки списка, отправки события, пагинации и синхронизации состояния будут обсуждаться отдельно.

## Публичный интерфейс генератора — УТВЕРЖДЕНО 2026-11-13

Модуль Widget предоставляет **одну публичную Python-функцию**, принимающую **список строк `list[str]` и заголовок `str`** и возвращающую **готовый HTML Widget как `str`**. Обновлённый публичный контракт (утверждено 2026-11-13):

```python
def render_station_widget(stations: list[str], title: str) -> str:
    ...
```

- `stations` — весь готовый непустой список, сформированный существующим кодом TrainBot; генерируемый Widget отображает данные, не обращаясь к РЖД.
- `title` — **произвольный заголовок, переданный вызывающим кодом**, который выводится в шапке Widget. Заголовок **не захардкожен** под «Станция отправления» или «Станция назначения». Это позволяет **повторно использовать интерфейс отображения списка** в других сценариях.
- Возвращаемый `str` — HTML/JS для визуального списка с локальной пагинацией срезом массива по значению `page_size` (по умолчанию 5), без вызова backend при перелистывании.
- **Отправка через Telegram API, получение событий, серверная проверка, FSM и сохранение значения — ответственность вызывающего кода.**

Имя `render_station_widget` пока **рабочее**, поскольку текущий сценарий — выбор станций; окончательное имя общего компонента можно согласовать позднее. **Для входных элементов согласованы два формата: `Текст_Значение` и `Текст` без разделителя.** Формат полезной нагрузки выбора ещё обсуждается; для текущего TrainBot формат `Название_Код` сохраняется. Исходный поисковый запрос, предусмотренный в UX-макете, **пока не передаётся отдельным аргументом**; способ его отображения остаётся открытым вопросом.

### Формат элемента списка — ПОДТВЕРЖДЕНО ПРИМЕРОМ ПОЛЬЗОВАТЕЛЯ 2026-11-13

**Утверждено для универсального Widget (2026-11-13):** каждый элемент `list[str]` допускает **два формата**: `Текст_Значение` или просто `Текст` (без разделителя `_`). Для TrainBot фактический список имеет вид `'Москва_2000000'`, `'Мосты_2101155'`, `'МстинскийМост_2004589'`; реализацию формирующего его обработчика отдельно ещё не исследовали.

- **Есть `_`:** разбирать строку по **последнему `_`** (например, `text, value = item.rsplit("_", 1)`). `text` отображать в основной строке карточки, `value` — мелкой второй строкой; перед ним выводить подпись из конфигурационного параметра `value_label` (например, `Код: 2000000` при `value_label="Код"`). При `value_label=""` отображать только значение без подписи. Значение сохранять строкой, без преобразования в `int`.
- **Нет `_`:** вся исходная строка — **только текст карточки**. Вторую строку, подпись из `value_label` или выдуманное значение **не показывать**, независимо от значения настройки. Сохранять фиксированную общую высоту виджета и раскладку по утверждённому макету.
- Оба варианта должны поддерживаться **в одном входном списке**, без отдельного режима или дополнительного публичного параметра.
- На этапе реализации обеспечить безопасное экранирование/сериализацию перед вставкой данных в HTML/JS; некорректные элементы не должны создавать ошибочную станцию или XSS.
- **Не согласовано:** источник и способ отображения исходного поискового запроса в шапке при параметрах `stations` и `title`. Для строк до 64 байт передаётся исходный текст, для более длинных строк — сокращённый по согласованному правилу: текст до `_` либо вся строка без `_` до пяти символов с точкой. Коллизии разрешены правилом «первый сохраняется, последующие пропускаются»; при остаточном превышении лимита элемент пропускается с `WARNING` в серверном логе.

## Ограничение данных при выборе — УТВЕРЖДЕНО 2026-11-13

- **Лимит Telegram для `TelegramWidget.request(data)` / `widget_query.data`: 1–64 байта UTF-8.** Проверять размер после `encode("utf-8")`, не по количеству символов. Источник: https://core.telegram.org/bots/widgets.
- **Обычный случай (до 64 байт включительно):** при выборе отправлять **всю исходную строку элемента**, точно как передано в `list[str]`: `Москва_2000000` → `Москва_2000000`, `Другой вариант` → `Другой вариант`; не отправлять индекс или только часть после `_`.
- **Новое решение пользователя (2026-11-13): если исходный элемент длиннее 64 байт**, **не удалять его из списка**, а **сократить первую (текстовую) часть перед последним `_` до первых пяти символов**, добавить точку `.` и **сохранить часть после `_` без изменений**. Например, для демонстрации формата сокращения `Ажжэжэлоло_200` → `Ажжэж._200` (исходный короткий пример сам по себе не превышает 64 байта, поэтому на практике не сокращается). Пользователь привёл пример `Ажжэy._200`; точные первые 5 символов данной исходной строки дают `Ажжэж`, поэтому в спецификации указан результат посимвольного правила. Сокращение применяется **только при превышении порога**.
- **Повторно проверять размер сокращённой строки. УТВЕРЖДЕНО (2026-11-13):** если она всё ещё длиннее 64 байт UTF-8 (например, из-за части после `_`), **пропускать такой элемент при подготовке итогового списка для Widget и записывать `WARNING` в серверный лог**. Не вызывать `TelegramWidget.request()` с недопустимым значением. В предупреждении фиксировать причину, индекс элемента и размер в байтах; не писать без необходимости полную исходную строку, содержащую пользовательские данные. Если после фильтрации список пуст, Widget не отправлять — применяется ранее утверждённое правило непустого списка.
- Сокращённая строка **не эквивалентна исходному идентификатору**. При реализации сервер должен проверять соответствие выбранной строки исходным разрешённым результатам; сохранять однозначное соответствие «отправляемая строка → исходная строка». Нельзя доверять изменённой строке как подтверждённому исходному значению без проверки.
- **УТВЕРЖДЕНО (2026-11-13):** если исходная строка **не содержит `_`** и занимает более 64 байт UTF-8, сокращать **всю строку до первых пяти символов** и добавлять точку `.`. Например, для иллюстрации вида `ОченьДлинноеНазвание` → `Очень.`; фактическое сокращение выполняется только при превышении 64 байт. Строка без `_` длиной 1–64 байта передаётся полностью. После сокращения повторно проверять лимит.
- **УТВЕРЖДЕНО (2026-11-13):** если после подготовки к отправке две разные исходные строки дают **одинаковые данные выбора**, сохранять **первый элемент в исходном порядке**, а **последующие совпадающие элементы пропускать**. Не добавлять номера или другие суффиксы. Сравнивать именно готовые строки запроса, включая совпадения между сокращённым и несокращённым вариантами; итоговый список должен содержать только однозначные значения выбора. Это согласованное исключение из правила сохранения всех исходных элементов.
- **УТВЕРЖДЕНО:** элементы, которые остаются длиннее 64 байт после сокращения, исключаются из итогового списка с серверным логированием уровня `WARNING`; пользовательский сценарий ошибок и fallback при пустом итоговом списке остаётся за вызывающим TrainBot.

## Требования к оформлению конфигурации — УТВЕРЖДЕНО 2026-11-13

**Напротив каждого параметра конфигурации Widget обязательно указывать короткий комментарий в той же строке.** Комментарий объясняет назначение, единицы измерения (если применимо), особенности значения по умолчанию. Не оставлять недокументированных элементов конфигурации.

Пример **оформления**, не утверждение конкретного значения высоты или состава окончательного конфига:

```python
WIDGET_CONFIG = {
    "width": None,   # Ширина: None — автоматическая, число — фиксированная (способ применения согласовать отдельно)
    "height": 520,   # Фиксированная высота виджета, 520 — пример, не согласованное значение
    "page_size": 5,       # Максимум элементов на странице; настраивается, по умолчанию 5
    "value_label": "Код",  # Подпись перед значением во второй строке; пустая строка — без подписи
}
```

**УТВЕРЖДЕНО:** `page_size` — **настраиваемый параметр конфигурации**, а не константа внутри Widget; значение по умолчанию — **5 элементов**, как в утверждённом макете. Значение должно быть положительным целым числом. Оба действия локальны: пагинация по срезу массива и счётчик диапазона рассчитываются из текущего `page_size`. При значениях, отличных от 5, нужно проверить размещение карточек при фиксированной высоте; неизменная высота формы — ранее утверждённое требование.

**УТВЕРЖДЕНО (2026-11-13):** `value_label` хранится в `WIDGET_CONFIG` и задаёт подпись **перед значением во второй строке карточки** (например, `"Код"` → `Код: 2000000`). Значение `""` означает показ без подписи (`2000000`). Если входной элемент не содержит `_`, второй строки нет, поэтому `value_label` на него не влияет. `"Код"` — пример для станций, а не обязательная подпись для всех применений универсального Widget.

**Открытые технические вопросы:** допустимые значения `width` и единицы измерения для фактического Telegram API, конкретное значение `height`. Утверждено требование комментирования каждого элемента, но не окончательная форма всего конфига.

## Передача списка и пагинация — УТВЕРЖДЕНО 2026-11-13

- Существующий обработчик TrainBot формирует **весь готовый непустой список** станций и **однократно передаёт его Widget при создании**. Widget не обращается к РЖД и не запрашивает дополнительные страницы у сервера.
- Внутри Widget доступен **полный переданный массив** станций. Текущая страница формируется **локальным срезом массива** по настраиваемому `page_size` (по умолчанию 5), например `stations.slice(page * pageSize, (page + 1) * pageSize)` для нумерации страниц с нуля.
- Стрелки изменяют только **локальный индекс страницы**; для перелистывания **не отправляется widget_query** и не вызывается backend. Диапазон и активность стрелок рассчитываются по длине полного массива.
- Утверждённый UX сохраняется: фиксированная высота, постоянное место пагинации, пагинация видна даже при одной странице, обе стрелки на единственной странице неактивны.
- **Ограничение для следующего решения:** Telegram Bot API допускает HTML до 32768 байт UTF-8 и до 4096 байт после zlib(9), а `chat_data` — не более 1024 байт UTF-8. Поэтому способ упаковки полного списка (в HTML или в состоянии), проверку размера и действие при переполнении лимитов **ещё требуется согласовать**. Решение «передавать весь список» не отменяет платформенные ограничения. Источник: https://core.telegram.org/bots/widgets и https://core.telegram.org/bots/api.

## Что согласовать до программирования

- Передача исходного поискового запроса (в UX-макете он присутствует); способ встраивания итогового списка в HTML, проверка HTML-лимитов и поведение при их превышении; жизненный цикл исходных данных для серверной проверки выбранной строки. Коллизии одинаковой полезной нагрузки выбора разрешаются сохранением первого элемента и пропуском последующих; остаточное превышение 64 байт — пропуск элемента с записью `WARNING`.
- Поддержку `sendWidget`, `widget_query`, `answerWidgetQuery` в реально установленной версии aiogram и Telegram Bot API; существующий транспорт календаря переиспользовать, если применимо.
- Формат события нажатия на станцию и защиту от подмены кода, повторных/просроченных событий; обновление FSM только после серверной проверки выбранной станции.
- Поведение `Отмена`, удаление сообщения Widget, ошибки обработки нажатия; **fallback** на исходные inline-кнопки. Кнопки `Подтвердить` нет.
- Тесты: 1/0/много результатов, одноимённые станции с разными кодами, пагинация, закрытие, быстрые повторные нажатия, рестарт FSM, реальные Telegram-клиенты.
