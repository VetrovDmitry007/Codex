# Виджет выбора станций TrainBot — функциональные требования

- **Дата:** 2026-11-12
- **Статус:** частично согласовано; UX отдельных экранов продолжается, реализация не начиналась
- **Сценарий:** создание подписки «Отслеживание» и редактирование её станций тем же Widget.
- **Техническая архитектура:** [station-widget-architecture-2026-11-12.md](./station-widget-architecture-2026-11-12.md)
- **Независимо от календаря:** это самостоятельная спецификация, не модификация календарной

## Цель

Упростить выбор станции (города) отправления и назначения в подписке «Отслеживание», не заменяя существующий механизм поиска станций РЖД и FSM.

## Утверждённые UX-решения

1. **Один общий виджет выбора станции** для обоих направлений — «Откуда» и «Куда». Пользователь открывает его отдельно для каждого поля; в конкретном открытии виджет выбирает **только одну станцию** и показывает соответствующий заголовок. Не создавать две независимые реализации: внешний вид, алфавит, поиск, пагинация и подтверждение идентичны; различается только назначение выбранного значения.
2. **Первый экран — текущая станция и варианты замены (согласовано):** в верхней части показывается **уже выбранный ранее город для открытого поля** («Откуда» либо «Куда»), ниже отдельным блоком «Заменить на» размещаются четыре фиксированные станции — **Москва, Санкт-Петербург, Казань, Сочи** — и кнопка «Другие станции». Это текущая станция конкретной подписки/настройки, **не история последних выбранных станций**. Нажатие на вариант замены выделяет его, но не сохраняет до «Подтвердить». Если город ещё не задан, показывать **«Не выбрана»** и заголовок над предложенными вариантами **«Выбрать станцию»** вместо «Заменить на»; эти четыре варианта и «Другие станции» остаются неизменными.
3. Нажатие **«Другие станции» показывает алфавит** — не переводит автоматически на обычный ввод текста в чате. Каждое нажатие на букву **добавляет её к набираемому названию станции**. Под сеткой букв отображается это слово, справа от него располагается кнопка **«Поиск»**. Только её нажатие запускает поиск станций по набранному тексту; результаты затем предлагаются для выбора.
4. **Компактная форма:** первоначальный одноколоночный прототип имел 260 логических пикселей. Для нового двухколоночного вида при выводе результатов может потребоваться более широкий Widget: подобрать минимальную читаемую ширину на реальных клиентах, точное значение не утверждено.
5. Сохранение одной станции не должно автоматически устанавливать другую.
6. **Два состояния алфавитной формы (согласовано):** до поиска алфавит занимает основную ширину; ниже отображаются набираемое слово и **три кнопки** (в прототипе «⌫», «Очистить», «Поиск»; окончательные подписи уточняются). После нажатия «Поиск» алфавит **сужается и перемещается в левую часть того же виджета**, справа **одновременно** показывается список подходящих станций. Не скрывать алфавит и не переводить пользователя на отдельный экран. При правке запроса список может обновляться после нового нажатия «Поиск».
7. **Результаты и двухсторонняя пагинация (согласовано):** справа одновременно отображаются **до четырёх** найденных станций. Вместо кнопки «Ещё» показывать **стрелки «‹» (назад) и «›» (вперёд)** и счётчик показанных результатов, например `1–4 из 10`. При перемещении результаты текущей четвёрки **заменяются** следующей/предыдущей четвёркой, форма не растёт. На первой странице стрелка «‹» неактивна, на последней стрелка «›» неактивна; когда всего 4 результата из 4 или меньше, неактивны обе стрелки.

8. **Подтверждение выбранной станции (согласовано):** касание станции в списке результатов **только выделяет её**, но ещё не сохраняет ни имя, ни код в FSM. После выделения доступна кнопка **«Подтвердить»**. Лишь её нажатие инициирует проверку и сохранение выбранной станции и возврат в меню параметров; без подтверждения данные подписки не изменяются. При смене выделения до подтверждения сохранять только последнюю подтверждённую станцию. **Для четырёх популярных станций на первом экране действует тот же принцип:** нажатие лишь выделяет станцию, сохранение — только по кнопке «Подтвердить». До подтверждения состояние подписки не меняется. Уже сохранённый город отображается отдельно, не трактуется как новое выделение, а кнопка «Подтвердить» по умолчанию неактивна до выбора замены.

9. **Нулевые результаты поиска (согласовано):** если по введённому слову станции не найдены, алфавит остаётся в суженной левой колонке, а справа вместо списка выводится текст **«Станции не найдены»**. Поле набранного текста и кнопки исправления/повторного поиска остаются доступны. Выделенной станции нет; **«Подтвердить» недоступна**. Данные FSM не изменяются.

10. **Пустое поле ввода (согласовано):** когда не набрано ни одной буквы, кнопка **«Поиск» неактивна** и запрос к серверу не отправляется. При вводе хотя бы одной буквы кнопка становится активной; если стереть весь текст (вручную через «⌫» или «Очистить»), снова становится неактивной. Это отдельно от ситуации, когда поиск выполнен и сервер вернул ноль станций (п. 9).

11. **Использование при редактировании (согласовано):** при редактировании существующей подписки применяется **тот же общий Widget** выбора станции, без второй версии формы. Из меню редактирования его отдельно открывают для поля «Откуда» либо «Куда»; станция сохраняется только после «Подтвердить». До подтверждения прежняя станция остаётся без изменений. Способ обновления зависимых параметров подписки при смене маршрута решается в архитектуре отдельно.

12. **Закрытие без изменений (согласовано):** в правом верхнем углу **каждого экрана общего виджета** (популярные станции, алфавит, результаты) есть кнопка **«×»**. Нажатие отменяет текущий выбор, **не записывает кандидата в FSM, не изменяет сохранённую станцию и не меняет подписку**, а завершает взаимодействие с виджетом. Точное техническое удаление/сворачивание виджета из сообщения требует отдельной проверки по Telegram Bot API и относится к архитектуре. Не путать «×» с возвратом из алфавита на первый экран.

## Прототип первого экрана

Пример с ранее установленной станцией «Тверь» (иллюстрация, не данные пользователя):

```text
┌─────────────────────────────┐
│ 🚉 Откуда                 ×  │
│ Сейчас выбрано:             │
│ Тверь                       │
│                             │
│ Заменить на:                │
│ [Москва] [Санкт-Петербург]  │
│ [Казань] [Сочи]             │
│ [Другие станции]            │
│                             │
│ [Подтвердить]               │
└─────────────────────────────┘
```

«Подтвердить» неактивна, пока пользователь не выбрал новый город; прежний город остаётся сохранённым до успешного подтверждения замены.

Если значение не задано: `Сейчас выбрано: Не выбрана` и `Выбрать станцию` вместо `Заменить на`. Кнопка «×» справа сверху прекращает выбор без сохранения.

## Прототип алфавитного экрана — согласованный принцип расположения

Состояние **до поиска** — широкая сетка букв, набранное слово под ней, три управляющие кнопки:

```text
┌────────────────────────────┐
│ 🚉 Откуда              ×    │
│ А Б В Г Д Е                │
│ Ё Ж З И Й К                │
│ Л М Н О П Р                │
│ С Т У Ф Х Ц                │
│ Ч Ш Щ Ъ Ы Ь                │
│ Э Ю Я                      │
│ МОС                        │
│ [⌫] [Очистить] [Поиск]     │
└────────────────────────────┘
```

Состояние **после поиска** — алфавит остаётся на экране слева, но более узкой сеткой, а справа отображается список найденных станций (временные названия и количество элементов на макете лишь примеры). Слово и три действия остаются доступными; под результатами — счётчик и две стрелки для перехода между четвёрками:

```text
┌────────────────────────────────────┐
│ 🚉 Откуда                       ×    │
│ А Б В Г │ Москва                   │
│ Д Е Ё Ж │ Можайск                  │
│ З И Й К │ Моршанск                 │
│ Л М Н О │ Мостовская               │
│ П Р С Т │                          │
│ У Ф Х Ц │                          │
│ Ч Ш Щ Ъ │                          │
│ Ы Ь Э Ю │                          │
│ Я       │ ‹  1–4 из 4  › (неакт.)  │
│         │ [Подтвердить]*          │
│ МОС                                │
│ [⌫] [Очистить] [Поиск]             │
└────────────────────────────────────┘
```

* Кнопка «Подтвердить» доступна после выбора одной станции из результатов. До её нажатия станция не сохранена.

Переход — локальная перестройка расположения элементов в одном Widget; **фактическую поддержку анимации «сдвига» и минимальную ширину нужно проверить на Telegram-клиентах**. Поиск исполняется на сервере после нажатия кнопки, а не на каждом символе. Результаты в примере не являются подтверждённым ответом РЖД.

## Требует согласования

- **На будущее (не реализовано и не входит в текущий этап):** хранение истории и показ последних выбранных пользователем станций. Сейчас используются только четыре фиксированные станции из п. 2.
- Нужна ли ручная текстовая альтернатива для старых клиентов Telegram и для длинных списков станций (рекомендуется сохранить существующий ввод).
- Точная ширина и внешний вид на узких мобильных экранах.

## Границы

- Не менять обработчики календаря, бизнес-логику подписок, API РЖД, БД или рабочий код без отдельного поручения.
- Не переносить поиск станций из backend во встроенный произвольный JS-справочник.
